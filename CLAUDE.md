## Project Overview

XChat is a LAN chat application built with Tauri 2. It supports three platform targets from a single Rust core:
- **Desktop**: Tauri-based desktop app (macOS, Windows, Linux)
- **Android**: Native Android app via Tauri mobile
- **Web**: Headless web server mode (Axum HTTP/WebSocket with bundled frontend)

The application provides peer discovery via UDP, direct/group messaging with offline delivery, file transfer with 4-way parallel transfer and resume, and a desktop capture editor with annotation tools.

## Architecture

### Dual Frontend Structure

The project has two frontend codebases:

1. **`frontend/`**: React-based development frontend
   - `App.jsx` - Main React application
   - `xchat.js` - Core application logic with Tauri command integration
   - `CaptureEditor.jsx` - Screenshot annotation editor
   - `styles.css` - Application styles with CSS custom properties for theming
   - Built via Vite, outputs to `src/` for Tauri bundling

2. **`src/`**: Static production assets (bundled output)
   - Generated by `npm run build` from the React frontend
   - Contains `index.html`, `css/`, and `assets/` directories
   - This is what the Tauri app and headless web server serve

When making frontend changes, edit the React source in `frontend/` then run `npm run build` to regenerate `src/`.

### Rust Backend Structure (`src-tauri/src/`)

The Rust backend is organized into these key modules:

- **`main.rs` / `lib.rs`**: Entry points for desktop/mobile platforms
- **`server_main.rs`**: Headless web server entry point (Axum-based)
- **`commands.rs`**: Tauri command implementations (IPC bridge between frontend and Rust)
- **`db.rs`**: SQLite schema, migrations, and database operations
- **`web_server.rs`**: Axum HTTP/WebSocket server for web mode and file serving
- **`workspace.rs`**: Application state management, conversation/message handling
- **`peers.rs`**: Peer discovery, connection management
- **`network/`**: Networking modules
  - `discovery.rs` - UDP broadcast for LAN peer discovery
  - `messaging.rs` - P2P message protocol
  - `conversation_file.rs` - File transfer with 4-way parallel transfer
  - `protocol.rs` - Wire protocol definitions
  - `transfer.rs` - File transfer state machine
- **`capture_editor.rs`**: Screenshot capture and annotation editor logic
- **`capture_shortcut.rs`**: Global hotkey registration for screen capture
- **`android_fd.rs`**: Android-specific file descriptor handling

### Feature Flags

The Cargo.toml defines two feature sets:
- `desktop` (default): Tauri plugins, clipboard, screen capture (`xcap` on Windows/Linux, system screencapture on macOS)
- `web`: Minimal dependencies for headless web server mode

Shared code (database, networking, protocol) is compiled for both targets.

## Development Commands

```bash
# Install dependencies
npm install

# Desktop development (auto-reloads frontend and Rust)
cargo tauri dev

# Desktop dev with isolated database
cargo tauri dev -- -- --port 18888 --db-path /tmp/xchat-dev

# React-only preview (Vite dev server)
npm run dev

# Build production frontend
npm run build

# Run Rust tests
cargo test --manifest-path src-tauri/Cargo.toml --lib

# Check compilation (desktop)
cargo check --manifest-path src-tauri/Cargo.toml --no-default-features --features desktop --lib

# Check compilation (web)
cargo check --manifest-path src-tauri/Cargo.toml --no-default-features --features web --bin lanchat-web

# Run headless web server
npm run build
cargo run --manifest-path src-tauri/Cargo.toml --no-default-features --features web --bin lanchat-web -- --port 8888 --db-path /tmp/xchat-web

# Build installers for current platform
cargo tauri build

# See all build targets (deb, rpm, apk, web, etc.)
make help
```

### 在 Windows 上打 Android 包

`make apk` 在 Windows 上有三处会断，都不是代码问题，是环境限制：

**1. 符号链接权限。** `cargo tauri android build` 最后要把 `$CARGO_TARGET_DIR/aarch64-linux-android/release/liblanchat.so` 软链到 `app/src/main/jniLibs/arm64-v8a/`。Windows 没开开发者模式会拒绝（`SetNamedSecurityInfoW ... failed: 5`）。这时 Rust 已经编好了，手动补一步再跑 gradle：

```bash
cp "$CARGO_TARGET_DIR/aarch64-linux-android/release/liblanchat.so" \
   src-tauri/gen/android/app/src/main/jniLibs/arm64-v8a/
cd src-tauri/gen/android && ./gradlew assembleUniversalRelease \
  -x rustBuildArmRelease -x rustBuildArm64Release \
  -x rustBuildX86Release -x rustBuildX86_64Release
```

**2. `rustBuild*` 任务找不到 `cargo.bat`。** 模板硬编码了 `cargo.bat`，而 rustup 的 bin 目录里只有 `cargo.exe`。用上面的 `-x` 跳过即可（`.so` 由第 1 步手动提供）。任务名是 `rustBuildX86_64Release`，带下划线。

**3. `local.properties` 的反斜杠会被 Java properties 吞掉。** `sdk.dir=C\:\Users\...` 里的 `\U` `\w` `\A` `\S` 都是无效转义，会被直接丢掉，路径变成 `C:UserswangyAppData...`，gradle 报「文件名、目录名或卷标语法不正确」。只有冒号要转义，其余一律用正斜杠：

```properties
sdk.dir=C:/Users/<you>/AppData/Local/Android/Sdk
```

### Android WebView 版本决定 CSS 能不能用

Tauri 在 Android 上用的是**系统 WebView**，版本跟随设备，`minSdk` 是 24，老机器上可能非常旧（实测一台 Android 11 的 OnePlus 6 上是 **92**）。这带来两个必须注意的点：

**1. Vite 默认的 CSS 压缩会产出老 WebView 不认识的语法。** esbuild 会把 `@media (max-width: 859px)` 改写成范围语法 `@media (width<=859px)`，那是 Chrome 104 才有的。老 WebView 解析不了会**整条丢弃**，整个断点的样式静默失效——表现是移动端布局完全没生效，退回桌面布局，且控制台没有任何报错。`vite.config.js` 里的 `cssTarget` 已经把它压到 104 以下，**不要删**。

**2. `color-mix()` 要 Chrome 111+，`:has()` 要 105+。** 仓库里这两者用得很多，在没有回退值的地方，老 WebView 会逐条丢掉声明。需要视觉降级的位置，按 `tokens.css` 里 `oklch` 的写法给一行纯色回退：

```css
background: var(--surface);                                  /* 老 WebView */
background: color-mix(in oklch, var(--surface) 94%, transparent);
```

排查这类问题最快的办法是确认设备 WebView 版本：

```bash
adb shell dumpsys webviewupdate | grep "Current WebView"
```

### 其他 Android 端的注意事项

- **系统返回键不接管应用内导航。** 在会话里按返回会直接退出 App，而不是回到会话列表。需要的话要在 `MainActivity` 里覆写 `onBackPressed`。
- **改签名密钥后必须卸载重装**（`INSTALL_FAILED_UPDATE_INCOMPATIBLE`），**会清掉设备上的本地数据**。
- **长按菜单要屏蔽原生文本选择。** WebView 在长按约 400ms 后会启动文本选中，比应用自己的长按手势还早；菜单是挂在滚动容器之外的，容器上的 `user-select: none` 盖不到它，要在菜单元素上也加一遍。

`sign-apk.sh` 在 Windows 上也跑不通：它找的是 `build-tools/<ver>/apksigner`，而 SDK 里只有 `apksigner.bat`。手动签：

```bash
"$ANDROID_HOME/build-tools/<ver>/apksigner.bat" sign \
  --ks xchat-release.keystore --ks-key-alias xchat \
  --ks-pass pass:android --key-pass pass:android \
  --out xchat-aarch64.apk \
  src-tauri/gen/android/app/build/outputs/apk/universal/release/app-universal-release-unsigned.apk
```

## Key Conventions

### Database Schema
The SQLite schema in `db.rs` uses these core entities:
- `conversations`: Direct or group chats
- `messages`: Individual messages with delivery status
- `files`: File transfer metadata
- `peers`: Discovered LAN peers
- `settings`: Application configuration

When modifying the schema, ensure migrations are added to preserve existing user data.

### Tauri Commands
All frontend-backend communication goes through Tauri commands defined in `commands.rs`. When adding a new command:
1. Implement the function in `commands.rs`
2. Register it in both `main.rs` (desktop) and `lib.rs` (mobile)
3. Add permission in `src-tauri/permissions/commands.toml`
4. Update the relevant capability JSON in `src-tauri/capabilities/`

### Frontend-State Backend Pattern
The frontend is primarily stateless. Application state lives in Rust (`workspace.rs`), and the frontend fetches state via Tauri commands. This ensures desktop and web modes behave identically.

### Network Protocol
The UDP-based protocol in `network/protocol.rs` defines message types for:
- Peer discovery broadcasts
- Message delivery (direct and group)
- File transfer coordination
- Delivery receipts

Protocol changes must maintain backward compatibility or include a version migration path.

### File Transfer
Files use a 4-way parallel transfer protocol implemented in `network/conversation_file.rs`. Key features:
- Chunked parallel transfer for speed
- Resume capability for interrupted transfers
- Progress tracking and cancellation

### Screen Capture
The capture editor (Tauri commands in `capture_editor.rs`, React UI in `frontend/src/CaptureEditor.jsx`) supports:
- Rectangle, ellipse, arrow, pen, mosaic, text tools
- Undo/redo
- Pin tool (keeps editor open for multiple captures)
- Platform-specific capture APIs (xcap on Windows/Linux, system screencapture on macOS)

## UI Development Workflow

For UI changes:
1. Edit `frontend/src/` (React components, CSS, etc.)
2. Run `npm run build` to compile to `src/`
3. For desktop: `cargo tauri dev` will hot-reload
4. For web: `npm run build && cargo run ... --bin lanchat-web`

The `ui-ref/` directory contains design reference materials and prototype HTML for UI features.

## Platform-Specific Notes

### Android
- Native integration in `src-tauri/gen/android/`
- File operations use `android_fd.rs` for content URI handling
- Build APK with `make apk` (includes signing via `sign-apk.sh`)

### Web Mode
- Serves bundled `src/` assets via Axum
- WebSocket endpoint at `/ws` for real-time messaging
- HTTP API at `/api` for REST operations
- Build with `--no-default-features --features web`

### Screen Capture Dependencies
Linux requires: `pkg-config libclang-dev libxcb1-dev libxrandr-dev libdbus-1-dev libpipewire-0.3-dev libwayland-dev libegl-dev`
