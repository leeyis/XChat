# XChat Open Design 设计系统

> 设计系统 ID：`user:web-prototype-design-system`  
> 来源项目：Web Prototype（`2e0eb181-e830-4623-8775-3dc474f49cf9`）  
> 适用表面：桌面 Web / 桌面应用壳中的局域网通讯、文件中心与 AI 诊断界面

XChat 用克制的冷中性界面承载高密度通讯信息，以稳定设备身份和完整传输状态建立可信感。浅色与深色主题保持相同的信息层级；绿色只负责“当前、可执行、进行中”，不承担装饰。

## Product Context / 产品上下文

XChat 是面向局域网与跨 VLAN / WireGuard 场景的桌面通讯工具。用户在同一工作台中完成设备发现、单聊与群聊、文件收发、截图、设备备注、共享文件管理和 AI 网络诊断。

设计优先级依次为：

1. **身份可信**：MAC 地址是稳定主键；备注、主机名、IP、在线状态和发现方式共同解释设备是谁。
2. **状态完整**：文件阶段、进度、速度、大小和下一步动作同时可见。
3. **密度可读**：固定窄栏承载导航与列表，主工作区获得最大宽度，辅助信息按需展开。
4. **反馈明确**：所有操作以禁用、聚焦、进度、收据、Toast 或确认对话框形成闭环。
5. **桌面原生感**：紧凑、低装饰、边界清晰，不借用营销页式大色块和空泛卡片。

## Visual Foundations / 视觉基础

### 视觉姿态

- 背景冷静、结构清楚、装饰克制；层级主要来自分栏、边界、留白和文字权重。
- 绿色不超过每个工作区两个高注意力用途：当前选中项与主动作，或当前进度。
- 选中会话使用整行绿色；主导航当前功能只改变图标颜色，避免两个选中语言互相争抢。
- 圆角是桌面控件的软化手段，不把所有内容包成独立卡片。
- 阴影只用于浮层、模态框、悬浮传输条和可拖离表面的对象。
- 信息与动作靠近：文件动作在文件状态旁，设备管理在身份详情里，发送工具固定于输入容器底部。

## Color / 颜色

### 核心颜色

规范令牌由 [`colors_and_type.css`](colors_and_type.css) 提供。六个核心令牌不得被组件局部覆盖。

| 角色 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `--bg` | `oklch(0.975 0.004 75)` | `oklch(0.17 0.01 70)` | 工作区背景、输入容器内层 |
| `--surface` | `oklch(1 0 0)` | `oklch(0.22 0.012 70)` | 面板、气泡、对话框 |
| `--fg` | `oklch(0.23 0.015 70)` | `oklch(0.93 0.005 75)` | 主文字、关键图标 |
| `--muted` | `oklch(0.55 0.012 70)` | `oklch(0.69 0.01 75)` | 次要信息、占位、时间 |
| `--border` | `oklch(0.89 0.008 70)` | `oklch(0.32 0.012 70)` | 分栏、输入和卡片边界 |
| `--accent` | `oklch(0.659 0.145 159.36)` | 同浅色 | 选中、主动作、发送、进度 |

辅助颜色来自源原型：

- `--danger: oklch(0.58 0.20 27)`：删除、失效文件、未读徽标。
- `--success: oklch(0.58 0.14 150)`：在线状态、成功反馈。
- `--warning: oklch(0.70 0.16 80)`：警告与系统提示。
- `--rail` / `--rail-fg`：主导航专用冷灰表面与图标色。
- `--avatar-1` 至 `--avatar-8`：确定性设备头像底色；按稳定设备 ID 映射，不随机变化。

颜色使用规则：

- 绿色实底上的文字使用 `--on-accent`，禁止将 `--fg` 直接放在绿色上。
- 聚焦环用 `color-mix(in oklch, var(--accent) 12%, transparent)`，不另造蓝色焦点。
- 危险动作只有在动作本身、错误摘要和确认主按钮上使用红色。
- 文件类型可用源原型中的紫色与橙色轻提示，但不能超过绿色主层级。
- 深色主题只替换背景、表面、文字、边界与导航色；`--accent` 保持不变。

## Typography / 字体

- **界面与正文**：`-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", system-ui, sans-serif`
- **展示标题**：`"Songti SC", STSong, SimSun, serif`
- **地址、速度、大小、时间、工具输出**：`ui-monospace, "SFMono-Regular", Consolas, monospace`

字号与行高：

| 层级 | 字号 / 行高 | 字重 | 用途 |
|---|---:|---:|---|
| 展示 | `32 / 1.18` | 600 | 设计系统预览与说明页标题 |
| 页面标题 | `18 / 1.3` | 680 | 文件中心、主要工作区 |
| 面板标题 | `16 / 1.35` | 650 | 会话与模态框 |
| 正文 | `14 / 1.45` | 400 | 消息、表单、一般内容 |
| 紧凑正文 | `13 / 1.4` | 400 | 会话摘要、辅助说明 |
| 元数据 | `11 / 1.3` | 400 | 时间、IP、MAC、速度、容量 |
| 微标签 | `10 / 1.2` | 550 | 标签、来源、厂商名 |

原则：

- 宋体只用于说明型展示标题和文档预览，不进入高频操作控件。
- 所有数字型元数据启用 `font-variant-numeric: tabular-nums`。
- 会话名可用 550–650；正文不使用过多粗体。
- 设备地址不缩写关键段；容器不足时整体省略并提供完整值。

## Spacing / 间距、圆角与阴影

### 间距

基础单位为 4px：

`--space-1: 4px`、`--space-2: 8px`、`--space-3: 12px`、`--space-4: 16px`、`--space-5: 20px`、`--space-6: 24px`、`--space-8: 32px`、`--space-10: 40px`

- 图标与文字：8px。
- 紧凑工具组：4px。
- 列表行左右内边距：10–12px。
- 工作区与消息边缘：20–24px。
- 模态框内容：20px；分组之间：18–24px。
- 预览与文档表面：24–40px，服务于审阅，不改变产品密度。

### 圆角

| 令牌 | 值 | 典型用途 |
|---|---:|---|
| `--radius-xs` | 5px | 标签 |
| `--radius-sm` | 7px | 小图标按钮、设备小头像 |
| `--radius-md` | 9px | 常规按钮、列表内控件 |
| `--radius-lg` | 10px | 输入容器、文件卡片、AI 卡片 |
| `--radius-xl` | 12px | 消息气泡、拖放区域 |
| `--radius-pill` | 999px | 徽标、状态点、筛选芯片 |

气泡采用方向性圆角：接收 `12 12 12 4`，发送 `12 12 4 12`。不要用过大的 20–28px 圆角把桌面工具做成移动端卡片。

### 阴影

- `--shadow-1`：轻微抬升，适用于消息图片和文件卡片。
- `--shadow-2`：浮层、模态框、Emoji 面板。
- 分栏、列表和普通卡片仅用边界，不用阴影。
- 深色主题继续使用与 `--fg` 混合的透明阴影，禁止纯黑厚重投影。

## Layout / 布局与构图

### 桌面骨架

标准四栏：

`56px 主导航 / 280px 会话或设备列表 / minmax(420px, 1fr) 主工作区 / 240px 可选信息面板`

- 主工作区是唯一主动伸缩列。
- 信息面板关闭时宽度归零，打开时以 200ms 过渡进入。
- 顶栏固定 56px；列表滚动和消息滚动互不干扰。
- 输入区在主工作区底部完整占宽，不悬浮在消息之上。
- 文件中心复用导航与来源列表，只替换主工作区。

### 响应策略

- `≥ 1100px`：显示完整文件表格与可选信息面板。
- `860–1099px`：隐藏低优先级文件来源 / 时间列；保留文件名、大小与动作。
- `< 1000px`：信息面板不可展开，身份详情通过模态面承载。
- `< 860px`：隐藏会话列表，保留 56px 导航与主工作区；文件表进一步简化。
- 最小触控目标为 44px；源原型中的 32–40px 紧凑控件仅用于鼠标优先桌面壳，响应式 Web 需扩大可点击包围盒。

## Components / 组件

### 主导航

- 56px 冷灰轨道；头像位于顶部，设置位于底部。
- 当前功能只将图标变为绿色，不添加背景块或侧边条。
- 未读徽标为红色胶囊；新设备点为绿色 8px 圆点。
- 悬停用 7% 前景色混合背景，140ms 退出。

### 会话行

- 高 64px，结构为 `40px 头像 / 弹性内容 / 时间与未读`。
- 选中态整行绿色，名称、摘要和时间切换为白色及透明白。
- 摘要单行省略；草稿前缀使用绿色，选中后切为白色。
- 离线设备降低名称对比度，并以空心状态点表示。

### 设备行与身份

- 高度至少 76px；主机名、地址与 MAC 用两行等宽元数据呈现。
- 备注名优先于主机名；`已备注`、`AI`、`手动` 是紧凑标签。
- MAC 是稳定身份，不因 IP 变化而改变头像颜色、备注或会话归属。
- 信息面板按“头像 / 在线状态 / 身份键值 / 文件或成员 / 管理动作”排序。

### 消息与收据

- 接收气泡使用 `--surface`，发送气泡使用 `--accent`。
- 最大宽度 65%；长文本可换行，不允许气泡推动相邻内容。
- 群聊消息在气泡上方显示“备注名 · MAC”。
- 时间与已读收据在气泡下方，收据由灰转绿表示送达。
- 多选模式给消息本体添加明确选择标记，并将发送按钮替换为红色删除动作。

### 消息输入器

- 输入器是完整边框容器：文本区在上，表情 / 截屏 / 文件工具栏在下，发送按钮位于右下。
- 聚焦时边框变绿并出现 3px 低透明焦点环。
- 空内容时发送禁用；Enter 发送，Shift + Enter 换行。
- 文本区在 66–200px 之间自动增高。
- Emoji 面板从工具栏上方向上展开，点击外部关闭。

### 文件卡片与传输

文件卡片必须同时显示：

1. 文件图标与名称；
2. 阶段：待上线、待接收、正在发送、已发送、未下载、正在接收、已接收、已失效；
3. 已传 / 总量；
4. 速度或阶段说明；
5. 对应动作：取消、下载、打开目录、重新请求。

进度使用实心绿色填充条。失效状态用红色边界或文字，不能只依赖图标。悬浮传输条用于持续任务摘要，不替代传输中心的完整状态列表。

### 文件中心

- 顶栏显示当前来源 / 类型和结果数。
- 类型筛选是 30px 胶囊，仅当前项用淡绿色表面与绿色文字。
- 文件表最宽时为 `图标 / 名称 / 来源 / 时间 / 大小 / 动作`。
- 文件预览、打开目录和删除是行尾动作；删除进入确认流程。
- 空状态说明如何调整来源、类型或搜索，不展示虚构文件。

### AI 工具卡片

- 思考过程、工具调用、工具结果与模型选择器共用 10px 圆角和边界。
- `summary` 至少 42px 高，正文区以顶部边界分隔。
- 工具输入 / 输出使用等宽字体；推理正文用 2px 中性左线。
- 错误只改变边界与摘要文字为危险色，不加整卡红底。
- 模型选择器使用原生单选控件并显示厂商元数据。

### 按钮、输入与浮层

- 主按钮：绿色实底、白字、轻微绿色阴影。
- 次按钮：表面底 + 边界；文本按钮：透明底 + 次级文字色。
- 危险按钮：只在确认或批量删除中使用红色实底。
- 输入高度 36px，常规圆角 8–9px；错误信息紧邻输入。
- 模态框由标题、正文、底部动作组成；危险确认默认将安全取消放在前。
- Toast 位于底部中央，2.5 秒后退出；状态点和文案同时表达结果。

## Motion / 动效与交互

- 标准缓动：`cubic-bezier(0.23, 1, 0.32, 1)`。
- 进入约 200ms；退出 140ms。
- 信息面板：列宽过渡 + 14px 横向位移 + 透明度。
- Toast：14px 纵向位移 + 透明度。
- 拖放层：160ms 淡入，持续任务可用低幅呼吸边界。
- 进度变化必须连续填充，不用轮播或装饰性闪烁代替真实状态。
- 支持 `prefers-reduced-motion: reduce`：移除非必要位移、呼吸和滚动动画。
- 所有图标按钮提供中文 `aria-label` 或 `title`；焦点状态与悬停同等清晰。

## Voice / 语气与品牌

语气是直接、具体、可恢复：

- 先说当前状态，再说原因或下一步：`已失效 · 来源文件已移动`。
- 操作使用短动词：`发送`、`下载`、`打开目录`、`重新请求`。
- 身份信息使用稳定术语：`MAC 身份`、`当前地址`、`发现方式`。
- 危险确认明确对象与后果：`将从本机删除文件，聊天记录仍会保留文件消息。`
- 不使用营销口号、拟人化夸张、模糊的“出错了”或没有恢复路径的提示。
- AI 输出区分思考、工具调用和工具结果，不把它们混为普通消息气泡。

## Assets / 资产与图标

- 参考截图保存在 [`assets/`](assets/)；预览卡片必须直接加载这些文件。
- 源原型中的线性 SVG 图标已整理为 [`build/xchat-icons.svg`](build/xchat-icons.svg)。
- 图标采用 24×24 视口、2px 线宽、圆端点和圆连接；通过 `currentColor` 继承状态色。
- 当前证据没有独立品牌 Logo、安装图标、托盘图标或字体文件，因此禁止凭空创造。设备头像继续使用确定性色块和内置卡通形象。
- 高信号交互源例保存在 [`examples/xchat-desktop-prototype.html`](examples/xchat-desktop-prototype.html)。

## Anti-patterns / 反模式

禁止：

- 把绿色扩展成大面积背景、渐变洗色或多个竞争强调色。
- 给主导航当前项添加底色或侧边装饰条。
- 用左侧彩色边线卡片表达所有状态。
- 将文件状态压缩成一行模糊小字，省略速度、阶段或动作。
- 用 IP 代替 MAC 作为稳定身份，或让头像颜色在重启后随机变化。
- 在每个标题旁放图标、用 Emoji 代替功能图标，或滥用卡通元素。
- 给所有分区加阴影和大圆角，制造“卡片套卡片”。
- 在桌面界面使用营销式超大标题、暖米色画布、紫色渐变或玻璃拟态。
- 隐藏错误原因、自动删除用户数据，或用仅颜色表达状态。
- 在窄屏硬挤四栏、保留水平滚动，或让文件名、地址和速度溢出单元格。

## Implementation Checklist / 实施检查

交付前确认：

- [ ] 六个核心颜色只来自令牌文件，浅深主题结构一致。
- [ ] 绿色不超过当前、主动作和进度三类角色。
- [ ] 数字元数据使用等宽字体和等宽数字。
- [ ] 设备身份同时能解释备注、主机名、地址和 MAC。
- [ ] 文件状态包含阶段、进度 / 大小、速度 / 说明和动作。
- [ ] 输入器、筛选、模态框、Toast、错误和空状态都有真实交互反馈。
- [ ] 860px 以下重新编排，不产生水平滚动。
- [ ] 所有指向性区域和主要控件都有稳定 `data-od-id`。
- [ ] 预览与 UI Kit 引用真实资产和共享令牌。
