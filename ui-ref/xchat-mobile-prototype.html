看完之后值得处理的几件事 按优先级

  • 缺陷

    深色主题下消息文字几乎不可读

    .bubble 的底色写死为 #9df29f，而文字色是 color: var(--fg)。深色主题把 --fg 换成了 oklch(0.93 0.005 75)（近白），气泡底色却没有任何 [data-theme="dark"] 覆盖 —— styles.css 里根本没有 [data-theme] 选择器，深色完全靠 tokens.css 换变量，所以这个写死的绿色漏了出来。

    这不是移动端独有的问题，桌面深色模式一样中招，只是手机上更容易被忽略。

    对比度实测
    浅色 #221c15 on #9df29f → 12.56 : 1 ✓
    深色 #eae7e4 on #9df29f → 1.09 : 1 ✗（WCAG AA 正文要求 4.5:1）
    另外 styles.test.js:116-117 用正则把 #9df29f 钉死了，所以这个 bug 不会被测试挡住。
    修法：把气泡色提成令牌，在 tokens.css 的 [data-theme="dark"] 里换一个深底亮字的绿。
  • 体验

    56px 的竖向导航条在手机上一直占着左边

    ≤859px 时列表和对话已经改成二选一了，但导航条没有跟着变 —— 它仍是左侧 56px 宽的竖排图标条。在 360px 宽的机器上这是 15.5% 的屏幕宽度，而且图标垂直堆在屏幕左上角，正好是最不好按的位置。

    主流移动 IM 的导航都在底部。这里要么把它挪到底部做成 Tab 栏，要么在窄屏下换成抽屉 / 手势。

  • 体验

    冷启动第一眼是一整屏空白

    mobileList 初始为 false，activeConversationId 初始为 null，两者叠加的结果就是首屏落在「选择一个会话」空状态上，而进入列表的唯一入口是导航条上那个 40px 的聊天图标。

    移动端首次进入直接给会话列表更合理；mobileList 的初值改成 true 大概就够了。

  • 待确认

    没有任何 safe-area 适配

    index.html 的 viewport 是 width=device-width, initial-scale=1.0，没有 viewport-fit=cover；CSS 里 env(safe-area-inset-*) 出现次数为 0。

    如果 Android WebView 走沉浸式（edge-to-edge），顶部导航条会顶进状态栏，底部输入区会被手势条压住。这个取决于 Tauri Android 的默认配置，需要在真机上确认 —— 上面六个画面我是按非沉浸式画的。

  • 体验

    100vh + min-height: 560px 在横屏下会撑破屏幕

    body 有 min-height: 560px，.app-shell 是 height:100vh; min-height:560px。手机横屏时视口高度只有 ~393px，min-height 会压过 height，整个壳被撑到 560px —— 顶部栏滚出视野，输入区也不再贴住可视区底部。

    另外 100vh 在移动浏览器上会随地址栏收放跳动，换成 100dvh 更稳。

  • 体验

    触控目标 40px，低于两个平台的下限

    窄屏规则是 .icon-button, .rail-button { min-width:40px; min-height:40px }。Material 建议 48dp，Apple HIG 建议 44pt，40px 两边都不够。有意思的是 .mobile-back 和 .mobile-close-list 单独设了 44×44 —— 说明标准是有的，只是没铺开。

    会话列表头部一行里，加号是 40、关闭是 44，肉眼能看出大小不一。

  • 体验

    消息快捷操作仍然依赖 hover

    .message-quick-actions 靠 opacity:0 + :hover 显形，触摸设备没有 hover。代码里用 .message:focus-within 做了兜底，所以点气泡后能出来，但发现性很差。

    对应的 .message-delete 在 ≤859px 已经改成常显了 —— 同样的处理可以推广到快捷操作（长按菜单是更常见的做法，代码里右键菜单 onContextMenu 已经写好了，接长按事件即可）。

手机框内为 ≤859px 断点的真实规则，直接取自 frontend/src/styles.css；颜色令牌取自 frontend/src/tokens.css；结构取自 frontend/src/App.jsx。
会话、设备、消息内容均为示意数据。设备 chrome（状态栏 / 手势条）是画上去的，用于说明比例，不在应用代码里。
