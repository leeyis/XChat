# 飞秋高价值能力复刻设计

- 日期：2026-07-31
- 状态：范围已确认，准备进入实施计划阶段
- 目标：在现有 XChat 的稳定身份、聊天、文件和 React/Tauri/Web 架构上，补齐飞秋最有价值的局域网协作能力。

## 1. 范围与成功标准

本项目不是重写飞秋，也不要求兼容飞秋的旧 IPMSG 协议；采用“功能复刻优先”，保留 XChat 当前协议和数据模型，只补齐高频用户闭环。

第一期必须交付：

1. 单聊/群聊闭环加固：离线补发、送达/已读、消息搜索、群公告、群文件共享、群成员状态。
2. 文件共享闭环：受管共享目录、好友/群共享文件列表、请求下载、密码保护、下载次数、断点续传、取消、失败重试和文件中心状态。
3. 远程协助闭环：发起请求、对方明确同意、共享桌面、双向语音通话、静音、结束会话，以及远程控制的单独二次授权。

明确排除：飞秋空间日志、云账号、公网中继、AI 诊断、端到端加密体系。应用管理器/插件、机器人/命令行、独立语音通话和日程提醒放到后续版本。AI Agent 平台也不进入第一期，但要在协议、会话类型和 capability 结构上预留安全扩展位。

成功标准：每个第一期能力都能在桌面端和 Web 端得到明确的能力状态；不支持的平台显示原因而不是无效按钮；消息、文件和远程会话均可恢复或安全结束；UI 在 `ui-ref` 规定的桌面、平板和窄屏断点下没有横向溢出。

## 2. 现有能力与复用边界

当前 XChat 已具备：

- `frontend/src/xchat.js` 的 `XChatModule`、Tauri/Web 双 adapter、统一事件归一化、离线/重连刷新和 capability 映射。
- `frontend/src/App.jsx` 的聊天、主机、文件中心、设置四模块，以及会话草稿、表情、截图、文件卡片和进度展示。
- Rust 的 `workspace.rs`、`db.rs`、`network/messaging.rs`、`network/conversation_file.rs`，已经覆盖稳定 direct ID、群同步、消息回执、文件状态、取消、断点续传、并行分块和可信文件路径。
- 设备身份模型以 MAC 为稳定键，保留 hostname、当前地址、发现来源、备注和在线状态。

第一期只新增三类能力，不做平行架构：

1. 共享文件目录和下载授权模型；
2. 群公告/群文件等群协作元数据；
3. 远程协助的短生命周期会话和媒体通道。

React 页面继续只通过 `XChatModule.getSnapshot/dispatch/subscribe` 访问运行时；Tauri commands 与 Axum handlers 只负责参数转换、权限校验和序列化，共享业务放在 Rust 核心。

## 3. 远程协助架构

### 3.1 控制面

在现有 WebSocket/TCP 控制面增加版本化的 `remote_session` 事件：

- `invite`：发起方、目标设备、会话 ID、能力列表和过期时间；
- `accept` / `reject`：目标方明确同意或拒绝；
- `capabilities`：屏幕、麦克风、扬声器、远程控制、平台权限状态；
- `mute` / `unmute`：本端麦克风状态；
- `control_request` / `control_grant` / `control_revoke`：远程控制的二次授权；
- `stop` / `expired`：任一方结束或超时。

会话状态只保存在内存中的受控 registry，带创建时间、双方设备 ID、状态和能力；默认 10 分钟无媒体心跳自动结束。媒体帧、音频和远程输入不写入 SQLite。可选的会话开始/结束日志只记录在本机诊断日志，不进入聊天历史。

### 3.2 媒体面

优先使用 WebRTC 传输双向音频和桌面视频，控制面负责信令和会话生命周期；不引入公网 STUN/TURN，局域网场景只使用局域网候选地址。

采集能力由运行时探测决定：

- 屏幕：`getDisplayMedia` 或平台原生屏幕采集后封装为 WebRTC 视频轨；
- 麦克风：`getUserMedia({audio:true})`，双方各自独立 mute；
- 扬声器：浏览器/系统默认音频输出，不在 XChat 内模拟音频设备；
- 远程控制：WebRTC DataChannel 或现有控制面承载受限 pointer/keyboard 事件，仅在授权后开放。

若目标运行环境无法获得屏幕或麦克风权限，发送具体原因并将对应 capability 置为 false；不能显示“已共享”但没有媒体流。

### 3.3 安全与可恢复性

- 发起请求、接受请求、允许远控均为显式动作；远控默认关闭。
- 远程方始终看到“正在共享/正在被控制”横幅、停止按钮和连接状态。
- 断线、窗口关闭、权限撤销、双方任一方停止都会清理 peer connection、控制 token 和 registry 条目。
- 控制事件只允许鼠标移动/点击、键盘按键和滚轮，拒绝 shell、文件系统或任意进程执行。
- 会话 ID、对端设备 ID 和 token 均不能由 HTTP 请求体中的地址字段推导；必须使用已发现/已授权的设备身份。

第一期实施顺序为：双向音频 + 单向桌面共享 → 双向桌面共享可选 → 远程控制二次授权。若平台媒体采集 API 在某目标上不可用，该目标保留聊天/文件能力，远程协助入口呈现不可用原因。

## 4. 共享文件与群协作模型

### 4.1 共享文件

新增 `shared_files` 表保存：稳定 ID、所有者设备 ID、受管文件路径、文件名、大小、SHA-256、MIME、是否需要密码、密码提示、下载次数、创建/更新时间和可见范围。路径必须位于应用管理的共享根目录内，所有下载通过稳定共享文件 ID 解析，禁止接受任意路径。

共享动作：

- 设置/取消共享目录中的文件；
- 查看全部、指定好友或指定群的共享文件；
- 请求下载/输入密码/取消请求；
- 下载进度、断点续传、失败重试和下载次数更新；
- 发送方撤销共享不删除已下载副本，历史消息仍保留“共享已撤销”状态。

### 4.2 群协作

在现有群会话和成员同步上增加：

- 群公告字段和置顶公告事件；
- 群共享文件来源；
- 群成员在线/离线和已读人数聚合；
- 群邀请、拒绝和版本冲突的明确状态。

不在第一期加入群管理员角色、入群审批和创建后复杂的成员编辑工作流；保留当前“创建群时选择成员”的边界。

## 5. UI 与交互约束

严格复用 `ui-ref/DESIGN.md`、`ui-ref/colors_and_type.css`、`ui-ref/ui_kits/app/shared.css`：

- 桌面骨架固定为 `56px / 280px / minmax(420px, 1fr) / 240px`，不增加第五栏。
- 主导航当前项只改变图标颜色；会话当前项整行绿色。
- 绿色只用于当前、主动作、发送气泡和活动进度；远程会话状态不使用新的强调色。
- 设备身份展示备注、hostname、当前地址、MAC、发现方式和在线状态。
- 文件列表和文件卡必须同时显示阶段、大小/进度、速度/原因和下一步动作。
- 远程协助入口放在聊天顶栏和设备详情动作中；会话状态在主工作区显示为可折叠面板或模态，不改变主导航结构。
- 远程面板至少包含：对端名称/MAC、连接状态、视频预览、麦克风状态、静音、结束、远控授权、权限错误和重连状态。
- 所有平台不可用能力使用禁用态 + 明确说明；所有危险动作使用确认流程。
- 保持浅色/深色同一层级，遵守 4px 间距、现有圆角/阴影和 reduced-motion 规则。

## 6. 错误处理与测试策略

### 错误处理

- 控制面错误返回可辨识 `code`、本地化文案和 `retryable`；React 只展示恢复动作。
- 远程会话错误分为权限拒绝、对端拒绝、能力不支持、媒体初始化失败、网络断开和超时；各自给出停止/重试/重新授权路径。
- 共享文件错误分为不存在、已撤销、密码错误、路径越界、磁盘空间不足、传输失败；不得泄漏真实本地路径。
- 所有取消、停止和结束操作幂等；迟到事件不能把终态恢复成活动态。

### 测试层级

1. JS 纯逻辑：能力归一化、远程会话状态机、共享文件筛选、权限文案、UI action reducer。
2. Rust 单测：共享文件路径边界、密码校验、会话 token/超时/幂等终态、群公告与共享文件迁移。
3. 双 feature 编译：desktop library/bin 与 web bin。
4. 双实例 Web 联调：发现、群聊、共享文件请求、取消/重试、远程邀请/拒绝/结束。
5. 桌面烟测：macOS 先验证屏幕权限、麦克风权限、双向语音、窗口关闭清理；其他桌面平台以 capability 矩阵报告可用性。
6. UI 视觉回归：`360×800`、`820×1180`、`1024×768`、`1366×768`、`1440×900`、`1920×1080`，检查无横向溢出、面板层级和状态可读性。

## 7. 后续 AI Agent 平台预留

后续版本将支持用户在自己的 XChat 客户端上配置模型连接、创建 Agent、为 Agent 绑定 MCP 和 Skill，并选择“仅本机可用”或“向局域网暴露”。本设计只固定边界，不在第一期实现模型调用和工具执行。

### 7.1 领域对象

- `model_connections`：提供商、显示名称、Base URL、模型名、协议类型和本机加密凭据引用。API Key/Token 永不写入发现帧、消息或日志。
- `agents`：Agent ID、名称、描述、系统提示词、模型连接引用、启用状态、版本、可见性（`private` / `lan`）和所有者设备 ID。
- `agent_mcp_bindings`：MCP Server 名称、传输类型、受控 endpoint、允许的工具列表和本机授权状态。
- `agent_skill_bindings`：Skill ID、版本、来源、启用状态和本机授权状态；Skill 内容不随发现广播发送。
- `agent_sessions`：以 Agent ID 作为逻辑会话目标，复用现有消息/回执/搜索模型；远程 Agent 对话不能伪装成普通设备或普通群成员。

### 7.2 发现与权限边界

- 局域网发现只广播 Agent ID、名称、版本、公开描述和能力摘要，不广播模型地址、密钥、MCP 凭据、Skill 源码或本机文件路径。
- `private` Agent 不进入局域网发现，也不能被远端通过猜测 ID 访问。
- `lan` Agent 的对话请求先到达用户客户端，由用户配置的暴露策略决定是否接受；默认只读对话，不允许远端改变 Agent 配置。
- MCP/Skill 执行必须经过本机授权和受控沙箱；远程用户只能调用公开 capability，不可直接注入任意脚本、路径或网络请求。
- 设备身份（MAC）与 Agent 身份分离：MAC 仍是设备稳定主键，Agent ID 只标识设备上的一个逻辑助手。

### 7.3 现在就要保留的接口位

- `Peer.capabilities` 保留可扩展命名空间，例如 `agent.chat.v1`，但第一期不显示 Agent 入口。
- 会话模型允许未来增加 `kind = 'agent'`，现有 direct/group 查询必须对未知类型安全失败而不是误当 direct。
- `XChatModule` 的事件归一化保留 `agent.changed`、`agent.session.changed` 名称空间；没有对应能力时 adapter 忽略事件。
- 共享 Rust 核心把“控制消息”和“业务消息”保持可区分，未来 Agent 工具调用不会污染普通聊天历史。

## 8. 第一阶段的非目标

- 不兼容飞秋 IPMSG 数据包；若未来需要互通，另开协议兼容项目。
- 不实现飞秋空间日志。
- 不实现云端账号、公网中继、端到端加密或组织级权限系统。
- 不把独立语音通话、应用插件、机器人/命令行和日程提醒混入第一期；它们复用远程会话/共享文件的能力基础，在后续计划中单独排期。
