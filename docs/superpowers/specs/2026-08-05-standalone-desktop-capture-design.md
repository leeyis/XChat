# XChat 无会话桌面截图设计

日期：2026-08-05

## 1. 背景

桌面截图快捷键当前依赖活动聊天会话。没有发现局域网主机、没有历史会话或尚未选择
会话时，`capture.start` 会把“没有活动会话”与“平台不支持截图”合并处理，错误提示为
“当前平台不支持截屏”。实际桌面截图后端在 macOS、Windows 和 Linux 上均可用。

新增的“复制截图”功能也使截图具备独立于聊天的用途，因此桌面截图不应再依赖局域网
主机或活动会话。

## 2. 目标

- macOS、Windows 和 Linux 桌面端在没有局域网主机、没有历史会话或没有活动会话时，
  仍可通过截图快捷键进入截图编辑器。
- 独立截图模式支持取消、钉图、复制和保存。
- 复制继续把当前选区与标注合成的 PNG 图片写入系统剪贴板，成功后关闭编辑器。
- 只有“完成并加入聊天草稿”依赖活动会话；独立截图模式不得创建无归属附件。
- 平台不支持、没有活动会话和屏幕录制权限失败必须使用各自准确的错误语义。

## 3. 非目标

- 不自动创建聊天会话、虚拟主机或本地自聊会话。
- 不改变 Web 截图是否可用的浏览器能力判断。
- 不为 headless Web 增加原生图片剪贴板复制行为。
- 不为 Android 增加截图能力。
- 不改变有活动会话时“完成”按钮把截图加入对应聊天草稿的现有流程。

## 4. 方案选择

采用“可选会话 ID”的独立截图模式。

前端在桌面截图能力可用时始终允许发起截图，并把当前活动会话 ID（如有）传给 Tauri；
无会话时传递 `null`。Rust 截图会话把 `conversation_id` 保持为 `Option<String>`，允许
`None`，但仍拒绝空白或超长的显式会话 ID。

不采用“只修改错误提示”的保守方案，因为它仍然无法满足无主机时截图、复制或保存的
要求。不采用自动创建本地会话，因为这会污染会话列表和持久化数据，并给消息语义带来
额外复杂度。

## 5. 界面与交互

- 有活动会话：截图编辑器行为保持不变；钉图、复制、保存和完成均可使用。
- 无活动会话：截图编辑器正常打开；钉图、复制和保存可使用。
- 无活动会话时，“完成”按钮禁用，`title` 和 `aria-label` 明确提示“请先选择一个会话”
  / “Select a conversation first”。
- 截图能力确实不可用时仍提示“当前平台不支持截屏”。
- 屏幕录制权限或系统抓屏失败时继续显示后端提供的平台专属错误。
- Web 截图编辑器不显示桌面原生“复制”按钮，避免调用不存在的 Web adapter 方法。

## 6. 数据流

```text
桌面截图快捷键
  -> 检查 capture capability
  -> 读取活动会话 ID（可能为 null）
  -> TauriAdapter.startCapture(conversationId)
  -> start_capture_editor(conversation_id: Option<String>)
  -> Rust 抓屏并保存 CaptureFile { conversation_id }
  -> 打开截图编辑器

独立截图模式
  -> 复制 / 保存 / 钉图：照常执行
  -> 完成：前端保持禁用，不生成无归属聊天附件
```

## 7. 边界与错误处理

- `capture=false` 时不得调用截图后端，返回 `capture_unsupported`。
- Tauri 桌面端 `capture=true` 且无会话时允许调用后端，传递 `conversationId: null`。
- Web 端保持原有会话要求和浏览器能力限制，避免扩大本次桌面修复范围。
- Rust 接受 `None`；`Some("")`、仅空白和超过 256 字符的 ID 仍返回“无效的会话 ID”。
- 截图编辑器从 pending capture 的 `conversation_id` 判断是否允许“完成”，不依赖主窗口
  的后续状态，避免截图期间会话列表变化造成错误归属。

## 8. 测试与验收

自动验证：

- 前端集成测试：Tauri runtime、`capture=true`、无会话时，`capture.start` 成功调用
  `start_capture_editor`，payload 为 `{ conversationId: null }`。
- 前端回归测试：`capture=false` 时仍返回 `capture_unsupported` 且不调用后端。
- Rust 单元测试：可选会话 ID 接受 `None` 和有效 ID，拒绝空白及超长 ID。
- Web 回归测试：Web runtime 不暴露原生截图复制能力。
- 运行完整前端测试、Vite 构建、Rust library tests、desktop/web compile check 和
  `git diff --check`。

桌面验收：

1. 断开或关闭所有局域网主机，确保会话列表为空。
2. 按截图快捷键，确认进入截图编辑器而非显示“当前平台不支持截屏”。
3. 选择区域后确认钉图、复制和保存可用，“完成”禁用并提示需先选择会话。
4. 点击复制并在支持图片粘贴的应用中粘贴，确认内容为选区及标注后的 PNG。
5. 创建或选择会话后回归“完成并加入聊天草稿”。
