# 备份恢复生产验证

实现范围：阶段三 P3-3，基线任务中心提交 `87bbd19`。界面沿用已批准原型，支持桌面本地目录和浏览器下载/导入，未修改截图功能。

## 实际行为

- SQLite 在线备份每次复制 256 页，在专用阻塞线程运行；批次之间释放源库读锁，让聊天写入继续进行。现有数据库为 DELETE 日志模式，因此没有使用长事务读锁或直接复制正在使用的数据库文件。[SQLite 在线备份说明](https://www.sqlite.org/backup.html)
- 归档包含固定结构的聊天记录数据库、可选偏好和本地完整附件。清单与每项内容分别校验 SHA-256，最后完整复验并原子发布；取消、磁盘空间不足和损坏输入不产生“已完成”记录。
- 导入先复制到私有暂存目录并校验版本、大小、摘要、精确表结构和数据库完整性。归档中携带的名字不能指定解压路径。
- 预览新增、重复及附件数量，偏好恢复默认不勾选；合并前创建当前数据库副本，合并在一个事务中完成，失败回滚。重复消息保留当前版本，已有群成员不被旧备份覆盖。
- 保留当前设备身份，映射备份中旧的“自己”。偏好仅包含主题、头像、通知、自动下载和传输并发；设备身份、网络地址、截图快捷键、远程授权及队列租约不迁移。
- 恢复记录有持久的 `restored_messages` 标记；即使状态被后续回调改变，也不能被发送租约、自动重连、任务重试或文件重试当作待发送消息。

## 已知边界

备份是完整本地归档，没有加密和压缩；未下载或正在接收的附件不包含在内。浏览器导入上限 8 GiB，更大的归档使用桌面导入。恢复不会自动补齐已存在消息的缺失附件。异常退出可能留下未发布的暂存目录/`.partial` 文件，它们不会进入备份完成列表。恢复前 SQLite 副本为故障恢复留存，不会伪装成可直接导入的 `.xchatbackup`。

真实慢盘、磁盘拔出及超大历史库尚未做硬件实测；故障回滚通过注入数据库写入失败验证。没有覆盖用户安装版或日常数据库，没有推送远程。
