# 阶段三远程协助与控制验证

实现对应已批准的 `437bfcc` 原型。入口位于单聊右上角，包含“请求对方协助”和“请求控制对方”；由共享方选择屏幕并明确允许查看或本次控制。生产界面没有角色切换、演示场景或假数据按钮。

## 实现与故障处理

- Rust 共享会话状态机、顺序信令、有界队列、邀请回查和设备身份验证；每个数据库最多一场会话。远程权限不入 SQLite，不随备份恢复。
- 屏幕/双向语音使用真实 WebRTC，控制事件走数据通道。Windows 以独立 xcap 捕获、SendInput 执行经过授权的有限事件；没有修改截图、编辑、贴图及快捷键链路。
- 接受前没有对端媒体连接；请求/连接/所有者/对端失联均有限时。暂停、切屏、撤销、结束和交互桌面失效立即废止控制；输入序号阻止重放。后台没有自动重连并恢复权限的路径。
- 共享方持续显示独立提示条。提示条按会话独立创建，旧条关闭不会结束新会话；不可见时停止发送画面或输入。关闭提示条结束本次协助。
- 双方独立麦克风静音、扬声器静音、音频设备选择；可以只接受画面、中途呼叫、单独挂断。画面暂停/控制撤销保持语音，语音失败保持画面，结束协助释放全部设备资源。
- 画质、帧率上限、减色作用于真实捕获/编码。延迟、FPS、分辨率和吞吐来自 WebRTC 统计，不使用演示数值。

## QA 中修复的问题

1. 暂停或切屏前发出的帧晚到，不能误结束协助或重新显示旧画面。
2. 切换共享源时旧轨道结束，不能关闭新的共享源。
3. 过期轮询、控制包和窗口关闭不能回写新权限或结束新会话。
4. 关闭授权对话框按“保持仅查看”处理，不留下永久等待授权。
5. 麦克风许可晚到、快速挂断再重呼，旧异步操作不能遗留轨道或关闭新麦克风；有针对性单测。
6. 滚轮使用非 passive 监听，避免控制时同时滚动本地画面；深色文字使用真实主题变量。
7. 窄窗口沟通栏只覆盖桌面画面，语音按钮保持可达，底层聊天输入器不穿透。
8. Android 不编译桌面窗口关闭 API，原生输入功能按平台能力关闭。

## 已知边界

- 仅 Windows 桌面可作为受控端。浏览器可以共享屏幕供查看，也可以操作已授权的 Windows 对端；浏览器与 Android 不会开放本机系统输入。
- 使用可信局域网 HTTP 信令与 WebRTC 媒体，没有公网中继、证书配对或抵抗主动局域网中间人的身份体系。跨网/公网远控不在本阶段范围。
- 普通权限进程不能操作管理员窗口和 Windows 安全桌面，不尝试提权或绕过。锁屏判断基于活动桌面，实际物理锁屏、UAC 和跨显示器硬件行为尚未人工验证。
- 未向用户日常应用注入测试键鼠；真实系统输入的正向硬件验收、两台物理电脑的长时稳定性、真实麦克风/扬声器回声效果仍需设备验证。
- 当前压缩为受限分辨率 JPEG → canvas → WebRTC 编码，性能取决于屏幕尺寸和设备；本轮没有作帧率保证。没有无人值守、剪贴板同步、系统音频、文件访问或系统服务控制能力。

首次 Android 检查因 NDK 未进入环境失败；补齐后发现本轮 close 缺少平台条件，修复后通过。浏览器脚本修复扩展后台页选择、缩进和参数错误后重跑；构建快照补齐既有测试所需配置文件后 190 项通过。备份阶段曾出现并发 Rust 测试的已有全局计数干扰，当前 Web 串行完整测试通过，没有据此声称该并发问题已修复。

Desktop 全量首次为 213 通过、2 个既有测试忽略、1 失败：原有端口占用恢复测试随机选择 TCP 55377，但该端口位于 Windows UDP 排除范围 55327–55426，触发 10013。夹具改为同时预占 TCP/UDP 再释放，完整重跑最终 214 通过、2 个既有忽略。未改生产网络端口策略。

同一端口恢复用例在 web feature 下定向复跑 1/1 通过。远程接入后的 [原生语音/任务/诊断回归](2026-10-10-phase3-final-tauri.json) 与 [备份恢复回归](2026-10-10-phase3-final-backup.json) 均通过。
