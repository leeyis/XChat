# XChat 反馈修复第四轮设计

日期：2026-08-11

## 目标

一次完成以下九项桌面端反馈，同时保持 Tauri 与 Web 适配器、单聊与群聊行为一致：

1. 引用消息可以加载并定位到原始消息。
2. 撤回消息会同步到单聊对方或全部群成员；离线成员上线后自动补发撤回。
3. macOS 群聊侧栏快捷操作更紧凑。
4. 解散群聊按钮使用明确的危险操作样式。
5. 转发窗口移除粉色底、双重输入框焦点和常驻粗滚动条。
6. 单聊侧栏操作使用带图标、带边框的按钮，底部会话状态操作居中。
7. 单聊使用双字头像，群聊使用 3–9 人宫格头像。
8. 消息时间改为类似微信的居中分隔，不再逐条显示日期时间。
9. 消息气泡和会话/设备选中状态使用指定颜色。

本轮不引入前端依赖，不改变已有消息 JSON 的兼容字段，不增加服务端或云端消息存储。

## 方案选择

采用复用现有消息表、消息状态和 `message_receipts` 的方案：

- `messages.status = 'recalled'` 表示本机已经撤回或收到远端撤回；查询聊天记录时过滤该状态。
- `message_receipts` 保存每个收件人的撤回请求时间和成功发送时间，充当已有逐收件人离线重试机制的扩展。
- 被撤回的消息只保留会话、发送者和稳定消息 ID 等 tombstone 信息，正文和文件展示字段清空。
- 收到撤回时即使本机尚无原消息，也创建 tombstone，阻止迟到或离线补发的原消息重新出现。

不采用独立撤回队列和 tombstone 两张新表，因为现有消息与回执已经具备相同的主键和逐收件人关系。也不采用只在内存中发送撤回事件的方案，因为它无法满足应用重启和对方离线后的补发要求。

## 引用消息定位

引用内容继续保存 `client_message_id` 和本机数据库 `message_id`。点击引用时优先使用稳定的 `client_message_id`，兼容旧消息时回退到 `message_id`。

前端向现有 `conversation.open` 动作传递其实际读取的 `targetClientMessageId` 或 `targetMessageId`。状态层先加载最近消息；目标不在当前页时继续使用现有历史分页向前加载，直到找到目标或没有更早消息。找到后滚动到视口中央并短暂显示高亮边框。

原消息已撤回、已被本机删除或不在数据库时不报错，也不改变当前会话；显示一次“原消息已不存在”的轻提示。

## 可靠撤回

### 本机发起

撤回只允许消息发送者操作。数据库在一次事务内完成：

1. 验证消息属于当前会话且发送者是本机。
2. 把消息状态改为 `recalled`，清空正文和不再需要的展示字段，保留稳定 ID、会话 ID、发送者 ID 和时间。
3. 为每个非本机收件人的回执记录撤回请求时间，并清空撤回成功发送时间。

事务提交后消息立即从本机列表消失。在线收件人立即发送现有 `MessageRecall` 协议；发送成功后标记该收件人的撤回已同步。单个成员发送失败不影响本机撤回，也不影响其他成员，失败记录留待重试。

### 离线补发

现有 `resend_for_peer` 在对方上线时先发送该成员尚未确认发送的撤回，再处理普通未送达消息。状态为 `recalled` 的原消息不得进入普通消息重发集合。

发送撤回成功即记录 `recall_sent_at`。当前协议不新增撤回确认包；TCP/WebSocket 写入成功视为本轮同步完成。若未来发现写入成功仍不能提供足够可靠性，再增加显式 recall ack，不在本轮预先扩展协议。

### 远端接收

接收端验证撤回发送者身份：已有原消息时必须与原发送者一致；没有原消息时，单聊必须来自会话对端，群聊必须来自该会话成员。验证后将已有消息改为 tombstone，或插入仅含身份信息的 recalled tombstone。

重复撤回必须幂等成功。收到迟到的原消息时，若稳定 ID 已对应 recalled tombstone，则忽略正文，不恢复消息。前端继续使用现有 `message_recall` 事件即时移除可见消息。

## 头像

使用浏览器原生 `Intl.Segmenter` 按用户可见字符切分名称；不可用时回退到 `Array.from`：

- 单聊：保留显式设置的自定义头像；否则显示名称末两个字符，只有一个字符时显示一个。
- 群聊：忽略旧的“群”占位字，按成员顺序取前 9 人。每格显示成员名称最后一个字符。
- 3–4 人使用 2 列宫格，5–9 人使用 3 列宫格；不足整行时末行居中。
- 同一头像组件覆盖会话列表、侧栏、转发选择和消息发送者，避免各处规则漂移。

群聊创建要求至少三位成员（含本机），因此正式群头像为 3–9 格；兼容异常旧数据时，少于三人仍按实际成员数渲染。

## 消息时间分隔

按升序消息流计算分隔：第一条可见消息显示时间；之后仅当当前消息距离“上一次已显示时间分隔的消息”达到 5 分钟时再显示。加载更早历史后重新从合并后的可见消息首条计算，避免分页边界重复时间。

中文格式：

- 今天：`HH:mm`
- 昨天：`昨天 HH:mm`
- 最近七天内：`星期X HH:mm`
- 同年更早：`M月D日 HH:mm`
- 跨年：`YYYY年M月D日 HH:mm`

英文界面使用同一判断规则和 `Intl.DateTimeFormat` 的本地化文本。日期判断基于本地日历日，不用简单的秒差判断“昨天”，避免跨午夜错误。

每条消息下方删除日期时间，只保留送达、已读、失败等状态。时间分隔作为消息列表中的独立居中元素，不参与引用定位和消息菜单。

公开资料对微信聊天时间的归纳一致：当天按约五分钟跨度显示，一周内使用星期，更早显示日期：

- https://cloud.tencent.cn/developer/article/1394668
- https://cloud.tencent.com/developer/article/1631171

## 视觉调整

### 群聊侧栏

- 群成员预览保持现状。
- “查看群成员、查找聊天记录、发布群公告、群聊设置”保持单列，按钮最小高度由 52px 调整为 44px，使用 12px 水平内边距和 8px 图标间距。
- 不使用固定比例拉伸，macOS 和 Windows 均由内容高度决定。
- 群聊设置中的解散按钮使用 `var(--danger)` 红色实底和浅色文字，并保留确认弹窗。

### 转发窗口

- 消息预览 icon 使用透明或中性 surface 底色，不使用 accent 混色。
- 留言框聚焦时只保留一层 2px 绿色焦点环；移除全局 outline 与组件 box-shadow 叠加形成的双框。
- 联系人列表自身承担纵向滚动，滚动条宽 3px，默认 thumb 透明，只在列表 hover/focus-within 时显示。

### 单聊侧栏

- “修改设备备注”和“清空聊天记录”改为纵向排列的带边框按钮，分别使用编辑和删除 icon。
- 清空按钮文字和 icon 使用危险色，但背景保持普通 surface；仍需确认弹窗。
- “置顶会话”和“标记未读”放在独立居中容器内，保留紧凑间距。

### 颜色

- 所有文本和引用消息气泡，无论发送或接收，背景统一为 `#9df29f`；文字使用深色以保证对比度。
- 文件卡片等非气泡附件保持现有 surface 样式。
- 会话列表和设备列表的选中背景精确使用 `#16ad6f`，对应的文字、时间和状态点维持足够对比度。
- 其他主按钮继续复用现有 accent token，不因选中状态要求而扩大颜色改动范围。

## 错误处理与兼容

- 撤回数据库事务失败：保留原消息并向用户显示错误。
- 某个对端发送失败：本机保持已撤回，待该设备上线重试。
- 收到非法身份撤回：拒绝并保留原消息。
- 重复撤回或先撤回后收到原消息：保持 tombstone，不恢复正文。
- 引用目标不存在：保持当前滚动位置并显示轻提示。
- 旧引用仅有数据库 ID 时继续支持本机定位；跨设备可靠定位只依赖已有稳定 client message ID。
- 已有 SQLite 数据通过 `CREATE TABLE IF NOT EXISTS`/`ALTER TABLE` 风格的窄迁移兼容，不要求清库。

## 代码范围

前端：

- `frontend/src/App.jsx`：头像、引用跳转、时间分隔、侧栏按钮结构。
- `frontend/src/xchat.js`：定位动作参数、撤回事件及消息归一化辅助逻辑。
- `frontend/src/styles.css`、`frontend/src/tokens.css`：侧栏、转发窗口、滚动条、气泡和选中颜色。
- `frontend/src/xchat.test.js`、`frontend/src/styles.test.js`：聚焦回归测试。

Rust：

- `src-tauri/src/db.rs`：recalled tombstone 和逐收件人撤回状态读写。
- `src-tauri/src/workspace.rs`：本机撤回事务、在线发送和上线重发。
- `src-tauri/src/web_server.rs`：远端撤回校验、幂等 tombstone 和迟到消息抑制。
- 必要时局部调整 `src-tauri/src/network/protocol.rs` 测试；不改变现有序列化字段。

不新增 Tauri command，不新增权限或 capability，不新增依赖。

## 验证

先建立可失败的聚焦回归测试，再修改实现：

- 引用点击传递正确 target 字段；目标在旧分页时能加载、找到并聚焦。
- 单聊和三人群聊撤回生成正确的逐收件人待同步状态。
- 在线同步成功后清除对应待办；离线重启后仍能在上线时补发。
- 接收端先收到撤回、后收到原消息时原消息不会出现；重复撤回幂等。
- 时间分隔覆盖连续消息、五分钟边界、跨午夜、昨天、一周内和跨年。
- 单聊双字头像及 3、4、5、9 人群头像布局。
- CSS 检查指定颜色、44px 群操作、单层焦点框、细滚动条和红色解散按钮。
