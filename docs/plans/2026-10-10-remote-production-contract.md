# 远程协助生产实现契约

已批准的界面以 `437bfcc` 及第二轮远程、双向语音设计文档为准。本文件记录实现约束，不增加评审步骤。

## 会话与授权

- 每个数据库同一时刻一场会话；请求 60 秒到期，接受后的连接限时建立。
- 明确区分请求协助（本机共享）与请求控制（对方共享）。屏幕共享方决定屏幕、查看/控制权限，接收方独立决定是否加入语音。
- UI 所有权令牌与对端信令凭据分开；本机 Tauri 命令或同源 localhost 页面取得 UI 所有权。公网/LAN HTTP 请求不能代替本机用户授予系统输入权限。
- 信令通过已验证设备地址交换，消息有序、有界、幂等；旧会话消息不能使终态恢复。
- 控制授权含本次会话的新随机令牌与世代。输入同时检查所有者、会话、控制授权、序号、屏幕范围及桌面是否可交互。
- 撤销、暂停、切换屏幕、结束、断线、锁屏、所有者页面失联均清理按键/鼠标状态并废止授权。重新连接需重新邀请，不自动恢复授权。

## 媒体与平台边界

- WebRTC 传输屏幕和双向语音，数据通道传输有界鼠标键盘事件；信令与媒体独立，不借用聊天发送队列重发过期请求。
- Windows 桌面使用独立的显示器捕获与输入模块，不导入或修改截图、截图编辑器、贴图、快捷键实现。
- 独立捕获仅在接受请求后运行，一次一帧，限制分辨率与帧率；结束或切屏后丢弃晚到的旧帧。浏览器使用系统屏幕选择器，浏览器共享仅支持查看。
- 共享方有持续可见的控制条，Windows 桌面置顶窗口允许收回、暂停、结束；本机失去交互桌面时停止会话。
- 暂停画面、切屏、撤销控制保持语音。单独挂断语音保留屏幕，结束协助同时关闭音视频和数据通道。
- 画质、刷新上限作用于真实编码/捕获参数；统计只展示 WebRTC 实际采集的值。普通权限应用不能控制管理员窗口和安全桌面。

## 验证

1. Rust 状态机检查两种方向、仅查看、控制授予/撤销、重复及过期消息、取消与接受竞态、所有者失联和输入边界。
2. 两个隔离后端、两个浏览器上下文进行真实 WebRTC 连接；仅屏幕/麦克风设备源可用明确标识的合成源替代。
3. 原生 WebView2 验证命令权限、独立屏幕枚举与取帧、控制条生命周期。输入校验使用替身执行器，不把测试按键发送到用户日常应用。
4. 原型对应界面、窄屏/深色、语音/文字沟通、结束后资源释放；最后执行 desktop/web 及可用目标检查。
