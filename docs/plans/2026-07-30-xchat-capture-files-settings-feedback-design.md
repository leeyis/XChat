# Xchat 截图、文件与设置反馈修正设计

日期：2026-07-30  
状态：已确认，待实施

## 背景

本轮反馈集中在三个现有交互面：

1. 截图编辑与钉图在图标、工具属性、文字能力、工具栏定位和选区稳定性上仍不够一致。
2. 消息输入框对本机文件的拖放、粘贴支持不完整，发送文件需要在消息气泡中可靠取消，同时移除重复的汇总进度横幅。
3. 设置导航缺少图标和“关于”入口。

实现采用增量修正方案，沿用现有 React 截图编辑器、绘制历史、Composer 文件草稿、传输取消后端和设置滚动导航。不得为本轮需求引入新的前端框架或重写现有模块。

## 目标

- 截图入口使用刀口纵向的剪刀图标。
- 不向马赛克工具展示无意义的颜色控件。
- 文字工具支持固定常用字体、字号、颜色、粗体和斜体。
- 钉图的标注工具栏始终浮在图片下方，不覆盖图片、不缩放图片。
- 钉图界面只保留“销毁”，移除“关闭/隐藏”的重复语义。
- 输入框可靠接收本机拖放文件与剪贴板文件。
- 截图选区创建和调整过程不抖动、不产生轻微缩放。
- 设置标签增加图标，并在最下方增加“关于”。
- 文件发送进度和取消操作只呈现在对应的消息气泡内。

## 非目标

- 不读取或枚举操作系统安装的全部字体。
- 不新增复杂文字排版能力，例如行距、字距、描边或多段落富文本。
- 不重做文件传输协议、数据库模型或文件中心。
- 不在“关于”中增加项目主页、许可证、更新检查或反馈入口。
- 不保留输入框上方的聚合传输进度或“全部取消”能力。

## 方案选择

采用现有模块内的增量修正：

- `CaptureEditor.jsx` 继续负责截图和钉图编辑状态。
- `capture-drawing.js` 继续负责可测试的几何计算、绘制操作和导出语义。
- `Composer` 继续负责文件进入草稿的浏览器与 Tauri 事件入口。
- 现有 `transfer.cancel` 数据流继续负责单项取消。
- 设置导航继续由统一的 section 元数据驱动。

没有选择先拆分大型组件的局部重构，因为会扩大当前脏工作区中的变更面；也不将全部拖放和粘贴改为原生 Rust 实现，因为 Web 与桌面路径仍需共享行为。

## 截图与钉图设计

### 截图图标

将截图入口的剪刀 SVG 替换为刀口纵向的轮廓。新图标沿用现有图标的尺寸、描边宽度、颜色继承和无障碍标签，不引入图片资源。

### 工具属性面板

属性面板按当前工具显示适用控件：

- 马赛克：只显示笔刷大小，不显示任何颜色选择器。
- 文字：显示固定字体列表、字号、颜色、粗体和斜体。
- 箭头、矩形和画笔等其他绘图工具：继续显示现有颜色和粗细控件。

固定字体列表使用带系统回退的常用字体族：

- 苹方/微软雅黑
- 黑体
- 宋体
- Arial
- 等宽字体

每条文字操作保存自己的 `fontFamily`、`fontWeight` 和 `fontStyle`。这些字段为可选字段；旧操作缺少字段时使用默认无衬线字体、当前默认粗细和正常字形。文字输入、选中已有文字、拖动、重绘和 PNG 导出必须使用同一组样式，避免编辑态与导出结果不一致。

### 钉图工具栏定位

右键“显示工具条”继续进入现有钉图编辑态并复用完整截图工具栏。进入编辑态时：

- 图片保持原始宽高和 1:1 坐标关系。
- 编辑窗口在图片下方增加透明工具栏区域。
- 工具栏定位在图片底边之外，并与图片保持固定间距。
- 屏幕下方空间不足时优先上移整个窗口，为工具栏腾出空间；不得把工具栏回退到图片内部。
- 标注画布尺寸与图片尺寸保持一致，额外工具栏区域不得参与导出。

退出钉图编辑但未销毁时，恢复普通钉图窗口尺寸和位置。

### 销毁语义

普通钉图窗口不再提供“关闭/隐藏”操作：

- 右键菜单删除“关闭”，只保留“销毁”。
- 图片上的关闭按钮改为销毁按钮，其标签、提示和行为都使用“销毁”。
- 针对钉图的关闭控件调用现有销毁路径，关闭窗口并清理临时截图。
- 从钉图标注编辑态返回只表示退出编辑，不销毁原钉图。

销毁操作保持幂等，重复事件不得报错或留下孤立临时文件。

### 选区稳定性

触发截图后，底图和选区在整个选择过程中保持同一坐标系：

- 移除截图底图、选区边框和控制点上的缩放动画、入场动画及会影响几何位置的 transition。
- 不使用 CSS transform 对截图底图或选区做初始化缩放。
- 指针按下后以固定 viewport 和设备像素比例计算选区，只更新 `x`、`y`、`width`、`height`。
- 窗口 resize 时统一刷新 viewport，不在一次拖动过程中改变坐标比例。

## 文件输入与传输设计

### 统一文件接收

Composer 使用一个归一化文件接收入口，将以下来源转换为现有草稿附件：

- `<input type="file">` 返回的 `File`。
- 浏览器拖放事件中的 `DataTransferItem` 和 `File`。
- Tauri 原生拖放事件中的本机绝对路径。
- 剪贴板事件中的图片、文档和其他文件类型。
- 系统剪贴板暴露的本机文件 URL 或路径。

桌面端优先使用 Tauri 已提供的本机路径；浏览器/Web 路径继续使用 `File`。同一次操作中的有效文件全部进入当前会话草稿，顺序按输入顺序保留。

目录不作为附件加入。一次操作包含目录和有效文件时，有效文件仍正常加入，目录名称汇总为一次明确提示。无法读取的路径或不再存在的文件同样只提示，不影响其他有效文件。

### 消息气泡中的取消

移除聊天区中位于输入框上方的聚合传输横幅及其相关布局。发送文件的以下信息只显示在对应消息气泡内：

- 文件名和总大小
- 当前状态
- 已传输大小、百分比和速度
- 进度条
- 单项取消操作

对仍处于可取消状态的发送文件显示“取消”。点击后立即禁用按钮并显示“取消中”，调用现有单项 `transfer.cancel` 数据流。后端确认后显示“已取消”；如果传输恰好先完成，则保留“已完成”，不得被迟到的取消响应覆盖。

取消请求保持幂等，重复点击、重复事件或已进入终态的传输不会产生第二次状态跃迁。

## 设置导航与关于

设置 section 使用统一元数据描述 `id`、双语标题和图标。现有标签按顺序增加图标：

- 身份：用户/身份图标
- 外观：太阳或调色图标
- 通知：铃铛图标
- 下载与传输：下载/文件夹图标
- 网络：网络/地球图标
- 快捷键：键盘图标
- 关于：信息图标

“关于”固定在导航最下方，并参与现有点击滚动和滚动同步高亮。对应内容区显示：

- 应用名称 `Xchat`
- 当前应用版本号
- 一句简短的局域网聊天与文件传输介绍

桌面端优先读取运行时应用版本；读取失败或 Web 环境不支持时使用构建内置版本。版本不可用不得阻断设置页渲染。

## 数据流与兼容性

- 截图工具控件只改变当前工具样式；新建文字操作时将样式复制进操作对象。
- 编辑已有文字时从该操作恢复字体、字号、颜色、粗体和斜体，提交后用现有历史替换操作。
- PNG 导出只读取操作自身样式，并为旧操作应用默认值。
- 文件拖放与粘贴只负责创建草稿附件；实际发送仍走现有 `message.sendFiles`。
- 文件气泡的取消按钮只传递该气泡对应的稳定 transfer ID。
- “关于”不修改设置持久化结构。

不改变现有消息序列化格式、WebSocket/HTTP 文件传输载荷或 SQLite 兼容性。

## 异常处理

- 不支持或不可读取的剪贴板项被忽略；如果一次操作没有任何可用文件，显示一次用户可理解的提示。
- 多文件拖放或粘贴采用逐项处理，单项失败不回滚已成功加入的附件。
- 取消失败时恢复可操作状态并显示错误；当前真实传输状态仍以后端刷新结果为准。
- 截图图片加载或导出失败沿用现有错误提示，不销毁仍可恢复的钉图。
- 版本读取失败使用构建内置版本，不显示空白占位。

## 验证

### 前端单元验证

- 工具属性可见性：马赛克无颜色，文字显示完整文字控件。
- 文字操作默认值、样式保存、编辑恢复、重绘和导出一致。
- 工具栏始终计算到图片外部的下方区域。
- 文件接收器覆盖浏览器 `File`、Tauri 路径、剪贴板文件、多个文件、目录和部分失败。
- 传输气泡在可取消、取消中、已取消、已完成状态下的按钮与文本。
- 设置 section 的顺序、图标映射、“关于”及滚动定位。

### Rust 与共享路径验证

- 运行现有 Rust 库测试。
- 检查桌面 feature 的共享核心编译。
- 检查 Web feature 的 headless binary 编译。
- 如粘贴本机路径需要新增窄平台命令，则同时验证命令注册、权限和 capability。

### 桌面冒烟验证

- 触发截图并反复拖选、移动和调整选区，确认无抖动或缩放。
- 检查每种截图工具的属性面板和文字导出结果。
- 钉图后右键显示工具栏，确认工具栏浮在图片下方且图片尺寸不变。
- 销毁钉图，确认窗口和临时文件均被清理。
- 从 Finder 拖入并粘贴图片、文档和其他文件，确认进入当前草稿。
- 发送大文件并从消息气泡取消，确认状态最终一致。
- 确认输入框上方不再出现聚合传输横幅。
- 检查设置标签图标、“关于”、版本号及中英文文本。

## 完成标准

上述九项反馈在桌面端实际操作中全部可复现验证；相关前端测试通过，Rust 桌面与 Web 路径完成窄编译检查，并且没有覆盖工作区中与本轮无关的现有修改。
