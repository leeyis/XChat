## 实际实现

### 发现和地址切换

- `network/peer_connection.rs` 集中管理发现候选、历史地址、固定地址及连接验证。UDP 在线通知更新发现状态；通过带目标设备 ID 的 WebSocket 握手验证后才提交新的有效地址。
- 每个设备的验证串行合并，验证和发现落库共用地址提交锁，避免较晚的发现写入覆盖已验证地址。收到新候选时按版本重新检查；未完成的变化保持待验证，后续扫描继续处理。
- 每轮最多 6 个候选、每设备 3 个并发探测、全局 12 个探测，单轮共享 7 秒期限。候选排序为最新固定地址、近期发现、历史有效地址及其余固定地址，避免积累的旧手工记录挤掉新 IP。
- 历史有效地址不随 UDP 缓存过期而丢失；已验证连接 30 秒后需要重验。自动候选核对实际出口接口是否启用；固定地址仍按已有显式配置处理。
- 网络和发现策略变化使验证缓存失效。发现唤醒使用保留版本的 watch 通知，避免广播任务忙碌时漏掉刷新请求。
- 桌面命令 `refresh_peer_connection` / `rediscover_peers` 与对应 HTTP 接口复用同一 Rust 流程，注册及权限已同步。主动刷新成功可提前唤醒待投递消息；例行 TTL 重验不清除消息退避。

### 发送及消息状态

- 首发、手工重试和自动补发共用持久投递路径，支持文本、引用、公告及群聊；重试沿用消息 ID，接收端沿用原有幂等落库。
- 写出消息仅进入等待回执；关联设备、会话及消息 ID 的 ACK 才确认送达。等待上限为 5 秒，超时表示未确认，不能据此断言对方未收到。
- 回执优先返回承载这条消息的连接，避免同一设备多条连接的全局映射把 ACK 路由到另一条连接。群资料同步与该群消息在同一条连接按序写入。
- 新增兼容的 `message_delivery_attempts` 表，记录收件人、尝试次数、下一次重试时间和最多 60 秒的崩溃恢复租约；不改变现有协议及历史状态字段含义。后台每 2 秒领取到期任务，每设备批次最多 4 条，实际网络重试受退避、租约及并发预算约束。
- 慢群同步、撤回、回执等控制流与正文分开使用并发槽；正文先执行，控制补发每轮总预算 4 秒。失败或取消的未完成项保留到下一轮。
- 前端使用新增 `delivery_state` 区分等待连接、发送中、等待回执、未确认、已送达、已读；原生与 Web 状态事件都刷新视图，迟到错误或历史查询不能把已送达/已读降级。

### 桌面界面

- 会话顶部及设备详情提供刷新地址，设备列表提供重新发现；分别显示发现在线与消息连接验证状态，以及有效地址、上次地址和验证时间。
- 桌面文件卡片收起原内联“打开”；右键菜单顺序为“打开文件 → 打开目录 → 另存为”。未完成、无本地文件、当前平台不支持的操作不可用，菜单支持键盘与边界定位。
