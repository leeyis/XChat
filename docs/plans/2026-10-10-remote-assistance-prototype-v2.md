# 远程协助原型第二轮

基线：726e3da。用户反馈：远程界面粗糙，应参考 QQ 与飞秋，明确“请求对方协助”和“请求控制对方”。本轮仍然只交付交互原型。

## 参考与取舍

- [QQ 远程协助的实际操作记录](https://cnzhx.net/blog/send-a-remote-assistance-request-from-qq/)：作为经典 QQ 交互参考，聊天上下文中区分请求控制和邀请协助；不是最新版全平台功能承诺。
- [西部数码使用企业 QQ 发起协助的帮助文档](https://www.west.cn/faq/list.asp?unid=2356)：邀请协助从具体聊天中的远程桌面入口发起。
- 本地飞秋 FeiQ2013 3.0.0.2：`analysis/feiq-20261009/FeiQ功能分析报告.md`，远程段落及 R8/S5，MENU 266 文件偏移 0x01146E00。可确认查看与控制的申请区分、全屏、色彩/压缩/传图频率设置；没有完整授权拒绝路径和反向入口证据。

采用双向意图入口、双方明确响应、持续会话提示和紧凑桌面工具栏。将飞秋底层显示调节归纳为易懂的画质与刷新设置；不复制旧版皮肤，也不把全部编码参数放到默认界面。

## 两条路径

| 操作 | 谁的电脑被共享 | 谁操作 | 谁授权 |
|---|---|---|---|
| 请求对方协助 | 我的电脑 | 对方 | 我选择共享屏幕；是否允许鼠标键盘由我明确选择 |
| 请求控制对方 | 对方的电脑 | 我 | 对方选择屏幕，允许本次控制、仅允许查看或拒绝 |

进入“请求控制对方”不必先发一个语义不符的查看请求。独立授权体现在接收方明确选择控制权限，而不是强制增加一次重复请求。仅查看状态下的后续升级仍需要共享方单独同意。

## 交互约束

- 发起前显示收件人、共享方向、预计权限，可填写简短协助说明。
- 等待、收到请求、拒绝、取消、超时、连接中各有明确反馈；尚未同意时不显示桌面。
- 接通后桌面占据主要空间，常用工具集中于顶栏，沟通面板可收起；共享方有明显的收回控制、暂停、结束入口。
- 仅查看不接受示意桌面的控制操作；共享方撤销、暂停、切屏、断线和锁屏立即使控制失效。
- 重新发起必须保持原来的协助方向；新会话不继承以前的控制授权。
- 原型画面、网络指标和聊天均为演示数据；不连接真实设备、不读取桌面、不发送真实消息。

## 评审方式

状态：第二轮交互原型完成，供用户评审；尚未进入生产实现。

预览：<http://127.0.0.1:18893/xchat-desktop-prototype.html?review=phase3&p3=remote&revision=2>。未启动服务时，在仓库根目录运行 `rtk proxy python -m http.server 18893 --bind 127.0.0.1 --directory ui-ref`。

1. 选择“请求对方协助”：选择自己的屏幕，可选是否允许控制，发送邀请。
2. 使用顶部评审栏“切到张三视角”，查看收到的请求并接受或拒绝。这是原型演示工具，正式界面不会出现角色切换按钮。
3. 重置后选择“请求控制对方”，切到张三视角，比较“仅允许查看”与“允许本次控制”。接通后可再次切换双方视角。
4. 在桌面工具栏尝试画质、缩放、展开和沟通；共享方可收回控制、暂停、切换屏幕或结束。场景菜单可模拟超时、网络波动、断线、锁屏及不可用设备。

画面比例、画质、刷新上限与色彩均为可交互的设计参数；演示的 12 ms / 30 FPS 等数值不是实测性能。“全屏”在原型中展开页面工作区，Esc 退出，未调用操作系统全屏或真实远控 API。授权后可点示意桌面的“展开”体验有无控制权的差异。

## 本轮验证

- 通过用户提供的 Chrome MCP 端点 `http://127.0.0.1:12306/mcp` 验证：48 项交互断言全部通过，包含双向意图、明确授权、仅查看降级、拒绝、撤销、取消竞态、重试方向与旧模块入口回归。
- 78 组布局检查全部通过：1000 / 860 / 390 px × 浅色 / 深色 × 13 个状态或页面。核对工作区、对话框与共享方控制按钮不越出视口；这不代表真实移动平台远控能力已经具备。
- Chrome MCP 键盘事件：第一个 Esc 只关闭画质对话框并保留展开桌面，第二个 Esc 退出展开。最终捕获零未处理异常。
- `rtk proxy node --check ui-ref/assets/stability-phase3-review.js` 和 `rtk git diff --check` 通过。仅原型资源与文档有改动；未运行生产 Tauri / Rust 构建，未验证真实设备远控、输入权限或网络性能。
- 6 张视觉证据来自独立 profile 的无头 Chrome：临时 HTML 副本引用当前原型资源、关闭动画后渲染；窄图使用真实 390 px iframe。Chrome MCP 图像捕获此前报 image readback failed，因此未把这些图片标为 MCP 截图。

检查中修复了对话框 Esc 向上冒泡同时退出展开桌面的问题，以及暂停后标题仍表示正在共享的问题。早期浏览器检查读到了缓存的上一版资源；给 JS 增加版本参数并重新加载后，确认双入口节点存在才重新验收。响应式检查去掉不必要的逐状态定时等待，避免后台标签页计时器节流影响验证完成。
