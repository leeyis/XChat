# 截图原位贴图与菜单稳定性

2026-10-08。用户已批准直接框选、原位贴图和标注的原型；随后明确批准去掉菜单绿色焦点边框、删除“所属分组”。本记录补充并更新 2026-10-07 的截图验收。

## 当前交互

- 截图按钮和截图快捷键直接进入选区，不再打开截图工作台。
- 新贴图保留选区的屏幕位置与显示尺寸。标注保留已有贴图的缩放、旋转、翻转、透明度与位置。
- 右键菜单显示 `Ctrl+Shift+P` 鼠标穿透、`F3` 恢复交互；`Esc` 隐藏、`Shift+Esc` 销毁。菜单移除所属分组，键盘焦点使用浅色背景，不显示绿色边框。
- F3 直接恢复交互与隐藏贴图，不跳转到工作台。重新打开应用主窗口也可解除鼠标穿透，作为全局快捷键被其他程序占用时的恢复入口。

## 实现与原因

旧路径为了容纳菜单或标注工具，会修改贴图本身的原生窗口尺寸和阴影。Windows 阴影改变非客户区边界，恢复尺寸时容易多出透明区域，重复改窗也会闪动。现在原图窗口与控件窗口独立，菜单开关不改变原图的窗口边框、位置和尺寸。

菜单随贴图在后台预加载，关闭时隐藏并复用；每次打开只传最新视图设置，跳过 PNG 读取、解码和编辑文档读取。隐藏 WebView 的初始化失焦事件不会提前关闭菜单；真正的原生失焦、点击菜单空白区域和 Escape 可以关闭菜单。销毁贴图同时销毁所属浮层。

选区使用截图窗口客户区原点、物理像素比例及导出取整后的裁剪边界计算目标位置。窗口在隐藏状态完成目的显示器定位，再核对客户区偏移，最后显示。已有记录继续保存窗口外框坐标，避免改变旧数据的含义。

标注使用原图坐标到当前贴图的仿射变换；指针、文字输入框和选区控制点共用同一变换。原始大图的裁剪区域不再被重新缩放至全屏。

## Windows 实测

隔离实例：`com.xchat.pinqa20261008`，端口 18888，独立数据库。WebView2 CDP 仅用于该测试实例。显示比例 125%。测试创建的贴图均在结束后销毁。

| 检查 | 结果 |
| --- | --- |
| 真实屏幕框选 → 贴图 | 选区物理坐标 `(700, 400)`、尺寸 `500 × 300`；贴图客户区完全一致 |
| 上述贴图进入标注、取消 | 标注 CSS 边界 `(560, 320, 400, 240)`；退出后客户区位置与尺寸完全一致 |
| 连续 12 次右键、点击空白关闭 | 原贴图没有移动或 resize 事件，无底部新增高度 |
| 原生焦点切到另一贴图 | 菜单关闭，原图几何不变 |
| 裁剪大图、水平翻转、0/90/180/270 度标注 | 四种角度的选区与原贴图物理边界误差均为 0；包含关闭阴影和缩略图场景 |
| 标注矩形并保存回当前贴图 | 保存 1 条可编辑标注；原位置与尺寸不变 |
| 菜单开启穿透 → 调用 F3 共用恢复处理器 | 恢复鼠标输入，坐标、尺寸不变 |
| 复用菜单后切换阴影 | 下次打开显示最新勾选状态 |
| 复用菜单销毁 | 原图及所属菜单均销毁 |
| 菜单焦点样式、所属分组 | computed outline 为 none；无分组项 |
| 隐藏后 F3 恢复 | 原位恢复，已就绪的菜单继续复用 |
| 菜单打开时开始截图，再取消 | 原图恢复，旧菜单保持关闭 |

预加载后连续 20 次打开、点击空白关闭：同一个菜单 WebView 被复用，原贴图移动/尺寸事件为 0。右键 DOM 事件到菜单收到原生 focus 事件的时间为 26–56 ms，中位数 30 ms。该数值是本机事件链路测量，不是摄像机测得的鼠标输入到屏幕像素变化时间。

坐标、延迟和最终回归的[原始测量结果](2026-10-08-capture-pin-results.json)不包含屏幕图片。
