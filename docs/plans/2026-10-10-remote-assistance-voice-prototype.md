# 远程双向语音与聊天语音消息原型

基线：`0b1e461`。根据本轮评审，补充远程协助双向语音、微信式聊天语音消息，并移除顶栏重复的“刷新地址”。原型已完成并验证，待用户评审；生产录音、音频传输、远程协助和截图实现未改动。

## 评审入口

- [聊天语音消息](http://127.0.0.1:18893/xchat-desktop-prototype.html?review=voice-messages)：点发送按钮左侧语音图标，体验录制、取消与发送；收到的 13 秒气泡可直接播放。
- [远程协助双向语音](http://127.0.0.1:18893/xchat-desktop-prototype.html?review=phase3&p3=remote&revision=voice)：两种请求均可附带语音；用评审条切换双方角色，查看接听、静音、挂断等状态。

预览服务从仓库根目录启动：

```powershell
rtk proxy python -m http.server 18893 --bind 127.0.0.1 --directory ui-ref
```

## 聊天语音与刷新入口

界面依据用户给出的两张微信参考图：语音圆形图标紧邻发送按钮；录制时使用左侧取消、灰色胶囊、绿色波形、右侧绿色上箭头发送。保留文字草稿，录制时 Enter 不会误发文字。至少录制 1 秒才可发送，最长 60 秒，到达上限停止录制并等待发送或取消。

语音消息显示时长、送达/等待上线/发送失败状态，失败可原条目重试。收到的消息有未播放标记，点击播放、再次点击暂停，再点击继续；同一时刻只播放一条，切换会话或离开聊天停止录制和播放。每个会话独立保存本轮演示记录；支持缺失语音文件“重新接收”与麦克风不可用的恢复演示。

顶部“刷新地址”节点已移除，旧地址横幅改为引导右上角“更多”；更多中的刷新设备地址动作保留并验证可完成。

## 远程协助双向语音

两种远程请求均默认勾选“同时发起语音通话”，发起人可以取消；接收方明确选择是否同时接通语音。接受后即可边看桌面边交流，不需要额外打开通话窗口；也可只接受远程协助，再由任一方中途呼叫，对方接听或拒绝。仅查看状态同样可以通话。

通话条固定在桌面上方，收起文字沟通面板、展开桌面和窄窗口时仍可见。双方独立控制自己的麦克风、扬声器和输入输出设备，区分“我已静音”和“对方已静音”。语音不是按住说话，也不等于共享电脑系统声音。

| 操作 | 画面/控制 | 语音 |
| --- | --- | --- |
| 暂停画面、切屏或收回控制 | 按既有授权规则处理 | 保持通话 |
| 挂断语音 | 保持远程协助 | 结束，可重新呼叫 |
| 麦克风不可用、语音断线 | 保持远程协助 | 提示并允许重试 |
| 结束协助、远程断线或锁屏 | 结束共享与控制 | 结束关联通话 |
| 新建/重新连接远程会话 | 重新确认授权 | 不继承上次语音加入状态 |

## 原型与真实能力边界

- 远程实时语音、设备选择、通话时长与网络状态为界面模拟，不读取真实音频设备、不调用麦克风或发送音频。
- 聊天录制和收发也是模拟；播放气泡使用真实 HTML audio 播放本地 `ui-ref/assets/voice-message-demo.wav`，不是实际录下或从对端收到的声音。发送气泡按演示录制时长截取/循环同一样例。
- 样例由本机 Microsoft Huihui Desktop 合成，长 12.733 秒；文本为“这是一条语音消息演示。文件已经收到，我们一会儿一起检查网络设置。你也可以直接回复语音。”不来自用户录音。
- 评审工具明确标注模拟数据与本地样例。真实麦克风授权、编码、回声消除、设备切换、跨机传输、重连和性能需在批准原型后的生产阶段实现、验证。

## 验证结果与复跑

最终证据：[voice-prototype.json](../verification/2026-10-10-voice-prototype.json)。

| 验证 | 方法 | 结果 |
| --- | --- | --- |
| 原远程交互回归 | 用户提供的 Chrome MCP，仅原型标签 | 48/48 |
| 原远程交互复验 | 独立无头 Chrome CDP、新 profile | 48/48 |
| 远程语音、聊天语音与刷新 | 独立无头 Chrome，示例播放静音 | 55/55 |
| 布局 | 浅/深色 × 1000/860/390px × 16 状态 | 96/96 |
| 运行异常 | CDP Runtime 异常记录 | 0 |
| 视觉复核 | 独立无头 Chrome，同一套原型资源 | 6 张 |

在新的原型页面中依次执行现有 [远程回归脚本](../verification/2026-10-10-remote-v2-interaction-check.js)、[语音交互脚本](../verification/2026-10-10-voice-interaction-check.js) 和 [响应式脚本](../verification/2026-10-10-voice-responsive-check.js)。页面初始入口使用 `?review=phase3&p3=remote`，自动化需等待返回的 Promise；使用前台标签或独立 Chrome profile，避免后台计时器节流及其他操作干扰。布局脚本使用真实指定宽度 iframe，检查溢出、按钮、对话框和聊天可用高度；重新应用主题以免旧导航重置主题。脚本仅用于原型状态验证，不能证明生产语音性能。

静态检查：`rtk proxy node --check` 分别检查两个改动的交互 JS 和两个新验证 JS；`rtk git diff --check` 检查补丁。本轮未改生产前端/Rust，未运行生产构建、Tauri 或跨平台音频测试。

视觉检查发现并修复关闭详情栏仍占宽造成的横向溢出，以及窄窗口列表挤压聊天区；补强聊天区高度断言后，最后一次布局验证 96/96。早期因后台节流、错误 CDP 页目标得到的失败不冒充产品结论；已在隔离浏览器重验。临时客户端、浏览器 profile、session 信息不入库。
