# Xchat 0.1.0 桌面端完善设计

日期：2026-07-29  
状态：已确认方案 A；截图工具范围于 2026-07-29 补充确认

## 1. 背景与目标

本轮以 `ui-ref/xchat-desktop-prototype.html` 为视觉和交互基准，继续完善当前 React + Tauri 2 实现。保留并复用现有 Rust 局域网发现、消息、文件传输、SQLite 和 HTTP/WebSocket 能力；缺失的桌面交互在现有模块中补齐。

本轮交付目标：

- 将用户可见品牌统一为 `Xchat`，首版版本号统一为 `0.1.0`。
- 正确生成无白边的应用图标。
- 修复空状态布局、设置导航、macOS 窗口重开和设备信息周期闪动。
- 恢复表情输入。
- 将截图改为“截图 → 编辑/钉图 → 加入输入草稿 → 用户确认发送”。
- 支持输入文字的同时粘贴或选择图片，并通过一次发送操作发送全部内容。
- 在聊天双方直接渲染可用的图片内容。
- 让文件中心严格遵循最新原型，并消除失效路径报错。

## 2. 产品与运行边界

### 2.1 品牌和版本

- 所有用户可见名称使用精确写法 `Xchat`。
- 应用版本统一为 `0.1.0`。
- Tauri bundle identifier 改为 `com.xchat.app`。
- Android application/package、JNI 名称和 provider authority 同步使用 `com.xchat.app`。
- 新 identifier 对应新的应用数据目录；首版不迁移旧开发数据库和设置。

内部 Rust crate/bin 名称及局域网兼容标识（例如 `LANChat|ONLINE`）可以保留，避免无用户收益的改名和协议断裂。

### 2.2 客户端与服务端

普通桌面使用只安装 Xchat 客户端，不需要独立部署中心服务。客户端继续内嵌：

- UDP 局域网发现；
- 消息监听和发送；
- 文件传输；
- 本地 SQLite；
- 客户端需要的本地 HTTP/WebSocket 接口。

现有 headless web binary 保留为可选能力，但不作为普通客户端安装或运行前提。

## 3. 视觉与基础交互

### 3.1 应用图标

输入 PNG 可以直接作为源素材，不要求 SVG。

处理规则：

- 仅移除与画布边缘连通的近白背景；
- 保留纸鹤本身的白色区域；
- 按透明内容边界裁切、居中并留一致安全边距；
- 从同一透明正方形母版重新生成 macOS、Windows、Android 和网页图标。

验收：Dock、Finder、安装包和应用内 favicon 均无白色矩形边缘。

### 3.2 空状态

聊天列表、聊天主区、主机列表、主机主区和文件区的真实空状态都在各自可用滚动区域内水平、垂直居中。

- 列表标题和工具栏不参与居中区域计算。
- 搜索无匹配与数据真正为空使用不同提示。
- 主机真正为空时不保留没有内容的在线/离线分组标题。

### 3.3 设置导航

设置左侧导航改为有内边距的圆角导航项：

- 默认态弱化；
- hover 态轻量高亮；
- 当前项使用主题色背景与文字；
- 页面滚动时同步当前项；
- 点击项后平滑滚动至对应设置区；
- 使用 `aria-current="location"` 表达当前位置；
- 窄窗口点击后先关闭列表再定位内容。

## 4. 会话输入与表情

### 4.1 表情面板

在输入框工具栏恢复表情按钮，使用项目内固定 Unicode 表情集合，不新增 emoji 运行时依赖。

首版集合沿用原型：

`😀 😄 😂 🥰 😎 🤝 👍 👏 🎉 ❤️ 😮 😢 😡 🤔 🙏 💪 ✅ 📎 💻 📁 🚀`

交互规则：

- 面板锚定在表情按钮上方；
- 点击表情后替换当前选区或插入当前光标位置；
- 插入后恢复输入框焦点和光标；
- 点击外部、按 Escape 或切换会话时关闭；
- 表情作为普通文本沿用现有文本消息协议。

### 4.2 附件草稿

截图、粘贴图片、拖入文件和文件选择器选取内容后，都先进入当前会话的附件草稿，不立即发送。

输入区展示：

- 图片缩略图；
- 非图片文件卡片；
- 文件名和大小；
- 单项移除按钮；
- 文字输入仍可正常编辑。

附件草稿按会话隔离，仅保留在当前应用运行期；首版不做跨重启草稿恢复。

### 4.3 一次发送

点击发送后：

1. 发送非空文字；
2. 按草稿顺序复用现有文件发送链路逐项发送附件；
3. 成功项从草稿移除；
4. 失败项保留并允许重新发送。

“一次发送”定义为一次用户操作发送多个相邻的独立消息，不新增复合相册消息、事务或 wire protocol。这样可保持现有客户端和协议兼容。

## 5. 截图与编辑器

### 5.1 截图流程

macOS 继续使用系统区域截图能力。截图完成后不发送，打开一个单例、置顶的 Tauri 截图编辑窗口。

流程：

1. 用户点击截图或触发快捷键；
2. 系统选择截图区域；
3. 成功截图后打开编辑窗口；
4. 用户编辑后选择“完成”“钉图”或“取消”；
5. “完成”将导出的 PNG 加入当前会话附件草稿；
6. “钉图”打开无边框、始终置顶的图片窗口，不加入草稿且不发送；
7. “取消”清理临时截图。

首版同一时间只维护一个编辑窗口和一个钉图窗口。再次触发时聚焦已有窗口，避免重复窗口和状态竞争。

### 5.2 首版编辑工具

截图首版本必须支持：

- 矩形；
- 椭圆；
- 箭头；
- 画笔；
- 马赛克；
- 文本；
- 回退。

工具行为：

- 矩形、椭圆和箭头通过拖拽起止点绘制；
- 矩形和椭圆首版只绘制描边，不增加填充模式；
- 箭头为直线加箭头端点；
- 画笔支持颜色和粗细；
- 马赛克以画笔方式涂抹，对原始图像区域进行像素化；
- 文本点击画布定位并输入，支持颜色与字号；
- 回退撤销最近一次完整操作；
- 首版不增加重做、裁剪、旋转、编号、聚光灯或自动识别。

实现使用浏览器原生 Canvas 和离屏 Canvas，不增加图形编辑依赖。编辑操作保留为可重放的操作序列；每次变化从原图重新渲染，回退只移除最后一个操作，避免对已经合成的位图做脆弱的逆运算。

### 5.3 文件生命周期

- 原始待编辑截图位于临时目录；
- “完成”后的图片写入应用数据目录下的受管 `media/outbox`；
- 受管输出不会被现有临时截图清理逻辑删除；
- 删除未发送的受管草稿时清理对应文件；
- 删除消息或清理历史时，只允许删除受管目录内的文件；
- 用户自行选择的源文件绝不由 Xchat 删除。

## 6. 图片消息与安全读取

### 6.1 内联显示

常见图片扩展名或 MIME 类型在以下位置直接渲染：

- 当前用户刚加入输入框的草稿；
- 当前用户已发送且本地文件仍存在的消息；
- 对方发送并已接收完成的消息；
- 文件中心预览。

加载失败、尚未接收完成或不是图片时回退到现有文件卡片，不显示破损图片。

### 6.2 安全边界

不直接放宽公开 `/api/media`，避免本地 HTTP 服务暴露任意已发送源文件。

桌面端新增按 `message_id` 读取媒体的受控接口：

- 先从数据库读取对应消息；
- 复用现有可信路径校验；
- incoming 文件必须位于下载目录；
- outgoing 文件必须与数据库记录的确切路径一致；
- 未知消息、越界路径和不存在文件均拒绝；
- 前端收到二进制后创建 Blob URL，并在不再使用时释放。

## 7. 文件中心

文件中心以 `ui-ref/xchat-desktop-prototype.html` 为唯一布局基准。

### 7.1 左侧来源导航

- 全部文件；
- 群聊来源；
- 设备/联系人来源；
- 每项显示文件数量；
- 当前来源使用与原型一致的选中态。

现有“进行中、我接收的、我发送的、失败”不再占用来源导航；传输状态继续由传输 Dock/传输中心表达。

### 7.2 主内容

- 顶部显示当前来源标题和文件数量；
- 类型筛选芯片：全部、图片、文档、音频、视频、其他；
- 表格列：类型图标、文件名/方向、来源头像与名称、时间、大小、操作；
- 支持双击预览；
- 操作包括预览、打开所在文件夹和删除；
- 按原型在窄窗口逐步隐藏次要列；
- 无结果时在内容区域居中展示空状态。

类型首版根据文件扩展名分类，不新增文件分类依赖。

### 7.3 失效路径

传输完成与本地文件可用性分开表达。

- 后端快照为文件记录提供本地可用性；
- 本地文件不存在时，预览、打开和定位按钮禁用；
- UI 显示“本地文件不可用”，不弹出原始操作系统路径错误；
- 新的编辑截图保存在持久受管目录，避免完成后立即失效；
- 旧失效记录继续可见，但只作为历史记录展示。

## 8. 设备信息闪动

已确认根因：

- 广播线程和监听线程分别调用非确定性的本机网卡信息选择，可能得到两个不同 MAC；
- reply 报文固定携带内存 `0`；
- PeerManager 和数据库无条件覆盖已有值；
- 周期刷新把两组数据交替呈现在主机详情和会话侧栏。

修复规则：

- 使用标准库 `OnceLock` 在进程内只计算一次本机 hostname/MAC；
- 所有广播、reply 和快照复用同一份本机元数据；
- 收到 `available_memory_mb = 0` 时视为未知值；
- PeerManager 和数据库都不得用未知值覆盖已有正值；
- 正常正值仍可更新；
- 不通过 CSS 隐藏或延迟更新掩盖数据问题。

## 9. 会话信息与 macOS 生命周期

### 9.1 会话信息

- 会话信息按钮初始不选中；
- 进入或切换会话时侧栏默认收起；
- 用户点击按钮后才展开；
- 侧栏中的设备信息使用第 8 节稳定后的同一份数据。

### 9.2 macOS 窗口重开

保留点击关闭按钮后隐藏主窗口的行为。抽取唯一的“显示主窗口”逻辑，并由以下入口复用：

- 托盘点击；
- 单实例再次启动；
- macOS `RunEvent::Reopen`。

显示顺序为 `show → unminimize → set_focus`。因此主窗口被关闭隐藏后，再点击 Dock 图标可重新显示，无需退出进程。

## 10. 兼容性与非目标

本轮不做：

- 独立中心服务器；
- 消息协议重构；
- 原子批量/相册消息；
- 跨重启附件草稿；
- 多钉图窗口；
- 截图重做、裁剪、旋转和 OCR；
- AI 诊断；
- 旧开发数据库或配置迁移。

桌面和 headless web 继续共享 Rust 核心。截图编辑和钉图是 macOS 桌面能力；不支持的平台应明确返回“不支持”，不能影响聊天和文件传输。

## 11. 验证与验收

### 11.1 自动检查

- React/Vite 生产构建成功；
- Rust library tests 通过；
- desktop feature 编译通过；
- web feature 编译通过；

### 11.2 桌面烟测

- 截图取消不会创建消息；
- 七种编辑能力均可用：矩形、椭圆、箭头、画笔、马赛克、文本、回退；
- 完成后只加入输入草稿；
- 钉图后显示无边框置顶窗口；
- 可同时输入文字、粘贴多张图片并一次发送；
- 部分附件发送失败时只保留失败项；
- 收发双方都能在历史中直接看到完成的图片；
- 非图片继续显示文件卡片；
- 文件中心结构和原型一致，失效路径不再弹错；
- MAC 和内存不再周期交替；
- 所有空状态垂直居中；
- 设置导航正确跟随滚动；
- 隐藏主窗口后点击 Dock 图标可以恢复。

隔离开发运行使用独立端口和临时数据库目录，避免影响用户现有数据。
