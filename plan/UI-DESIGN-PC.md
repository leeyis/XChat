# XChat 桌面端 UI 设计说明书

> 目标读者：界面设计师 / 设计 Agent
> 范围：**仅 PC 桌面端**（Windows / Linux / macOS，Tauri WebView）。移动端与 Web 端不在本文档范围内。
> 版本：基于现有实现 v0.1.5 重新设计。产品更名为 **XChat**（原 LANChat）。
> 视觉参照：附带的深浅双版参考图（橙色主色、四栏布局、圆角方形头像）。**默认浅色**。

---

## 1. 产品定位

XChat 是局域网内的**免注册、无服务器**点对点聊天与文件传输工具。

三个定义产品性格的事实，设计时必须内化：

1. **没有账号、没有登录、没有好友关系。** 启动即分配随机用户名，同一网络的设备自动互相发现。没有"添加好友""通过验证""个人主页"这类概念。
2. **设备即联系人。** 列表里的每一项是一台机器，不是一个人。名字可以随时改，IP 会变，同一个人可能有三台设备同时在线。
3. **文件传输是第一等公民**，不是聊天的附属功能。用户很多时候打开它只为了把一个文件从笔记本推到台式机。

参照物是微信，但只借**信息架构**，不借业务模型。

---

## 2. 设计原则

1. **传输状态永远可见。** 文件传输有 8 个状态，任何一个都不能只用一行小字表达。用户需要随时知道"发出去了没有""还剩多久""失败了能不能重试"。
2. **设备身份要好认。** 局域网里同时在线 10 台设备是常态，其中三台可能都叫 `MacBook-Pro`。列表必须让人一眼分辨。
3. **零依赖可实现。** 前端是原生 HTML/CSS/JS，无构建步骤、无框架、无图标库、无 Web Font 下载。所有效果必须用手写 CSS + 内联 SVG 完成。
4. **浅色为默认，深色等价。** 参照图是同一套设计的双版实现。浅色是默认主题，深色不是"降级版"——两版的层级关系、对比度、状态可辨识度必须等价。橙色主色在两版中保持同一色值。
5. **不为对称造功能。** 微信有四个标签，XChat 只需要三个。宁可少一个也不要凑数。

---

## 3. 信息架构（核心改动）

### 3.1 当前问题

现在只有**一个**用户列表，同时承担"会话列表"和"设备名册"两种职责，排序规则硬编码为「未读 > 在线 > 名称字母序」。这导致：

- 局域网里 10 台在线设备全部挤在列表里，但用户只跟其中 2 台聊过
- 想找"刚才那个发文件的设备"和想找"书房那台机器"是两种截然不同的意图，却共用一个列表和一套排序

### 3.2 新架构

拆成两个列表。数据源本来就是分开的：SQLite 里的聊天记录 = 会话，UDP 发现的 peers = 设备名册。

参照图采用**四栏**布局，本设计沿用：

```
┌────┬──────────────────┬────────────────────────┬──────────────┐
│    │                  │                        │              │
│ 🙂 │  会话 / 设备列表  │        消息区           │  设备信息面板 │
│    │                  │                        │  （可折叠）   │
│ 💬 │                  │                        │              │
│ 🖧 │                  │                        │              │
│    │                  │                        │              │
│ ⚙  │                  │                        │              │
└────┴──────────────────┴────────────────────────┴──────────────┘
  56px      280px               自适应               240px
```

第四栏（右侧信息面板）是参照图相对现有实现新增的。它承载的内容在本产品里有明确对应物，不是凑数：设备详情（IP、端口、发现方式、最后在线）、本次会话的文件清单、以及「清空记录 / 删除设备」这类管理操作。

**默认折叠。** 桌面 IM 的主任务是读写消息，不是看元数据。折叠时消息区吃掉这 240px。顶栏右侧一个图标按钮切换，状态记住。窗口宽度 < 1000px 时强制折叠（否则消息区会被压到不足 420px）。

**左侧图标栏（56px 固定）**

从上到下：

| 位置 | 元素 | 说明 |
|---|---|---|
| 顶部 | 我的头像 | 点击打开「我」面板。头像下方叠加在线状态点 |
| 主区 | 💬 会话 | 有未读时图标右上角红色数字气泡 |
| 主区 | 🖧 设备 | 有新发现的设备时显示小圆点提示 |
| 底部 | ⚙ 设置 | 点击打开设置面板 |

图标用内联 SVG，24×24，线宽 2，`stroke: currentColor`。选中态：图标变亮 + 左侧 3px 高亮竖条。

**中栏（280px 固定，与现有实现一致）**

顶部是搜索框 + 操作按钮，下方是列表。会话页和设备页共用这个栏位，切换时替换内容。

**右侧内容区（自适应，最小 420px）**

聊天详情，或空状态占位。

### 3.3 为什么不做第四个标签

微信的「发现」（朋友圈 / 视频号 / 扫一扫）在 XChat 里没有任何对应物。不要发明一个。

## 4. 窗口与响应式

| 项 | 值 | 说明 |
|---|---|---|
| 默认尺寸 | 1100 × 720 | 现为 900×700。四栏布局下建议放宽，让信息面板首次展开时也不挤 |
| **最小尺寸** | **860 × 560** | **当前未设置，需要补。低于此宽度布局会挤爆** |
| 可缩放 | 是 | |

**断点（两档）**

- `≥ 1000px`：信息面板可展开
- `< 1000px`：信息面板强制折叠，消息区接管其宽度
- `< 860px`：不需要处理（由最小窗口尺寸保证）

窗口拉宽时，图标栏、列表栏、信息面板宽度固定不变，只有消息区伸缩。消息气泡最大宽度限制为消息区的 65%，避免超宽屏下一行文字横跨整屏。

## 5. 逐屏规格

### 5.1 会话页（💬）

**中栏顶部**

```
┌────────────────────────────────┐
│  🔍 搜索                        │
└────────────────────────────────┘
```

搜索框搜会话名和消息内容。高度 32px，圆角 8px，聚焦时边框高亮。

**会话列表项**

这是整个应用里最高频的组件，规格要精确。

```
┌──────────────────────────────────────┐
│ ┌────┐  张三                  14:32  │
│ │ 张 │  好的，文件收到了         ②   │
│ └────┘                               │
├──────────────────────────────────────┤
│ ┌────┐  MacBook-Pro           昨天   │
│ │ M  │  📄 季度报告.pdf              │
│ └────┘                               │
├──────────────────────────────────────┤
│ ┌────┐  书房台式机      ○      3天前 │
│ │ 书 │  [草稿] 那个配置文件...        │
│ └────┘                               │
└──────────────────────────────────────┘
```

| 元素 | 规格 |
|---|---|
| 行高 | 64px，垂直居中 |
| 头像 | 40×40，圆角 8px（不用圆形，方形更贴近桌面 IM），左边距 12px |
| 名称 | 14px / 500，单行溢出省略 |
| 消息预览 | 13px / 400，`--text-dim` 色，单行溢出省略 |
| 时间 | 11px，`--text-dim`，右上 |
| 未读气泡 | 右下，最小 18px 圆角胶囊，红底白字，超过 99 显示 `99+` |
| 离线标记 | 名称右侧一个 6px 空心圆点 + 名称降至 60% 不透明度 |

**头像方案（新增）**

当前没有头像系统。用**设备 ID 哈希生成确定性色块 + 名称首字符**：

- 从预设的 8 色调色板里按 `hash(device_id) % 8` 取色
- 中文取第一个字，英文取首字母大写，emoji 直接用
- LANClaw 机器人固定用 🤖 + 专属色

这是本次重设计里性价比最高的单项改动，请务必包含。

**消息预览文案规则**

| 消息类型 | 预览 |
|---|---|
| 文本 | 原文（截断） |
| 图片 | `[图片]` |
| 文件 | `📄 文件名.ext` |
| AI 消息 | 文本片段 |
| 有草稿未发送 | `[草稿] 输入框内容`，`[草稿]` 用强调色 |

**排序规则（改动）**

改为**按最后一条消息时间倒序**，与微信一致。置顶会话排在最前。

废弃现有的「未读 > 在线 > 字母序」——在会话列表里，"这台设备是否在线"不是排序依据，只是一个状态标记。

**右键菜单**

置顶 / 取消置顶、标记未读、清空聊天记录、删除会话。

**空状态（新增，当前缺失）**

没有任何会话时，中栏显示插画占位 + 文案「还没有聊天记录」+ 副文案「去『设备』页看看局域网里有谁在线」+ 一个跳转按钮。

### 5.2 设备页（🖧）

```
┌────────────────────────────────┐
│  🔍 搜索设备              ＋    │
├────────────────────────────────┤
│  在线 · 3                      │
│  ┌────┐ 张三                   │
│  │ 张 │ 192.168.1.42:8888      │
│  └────┘                        │
│  ┌────┐ MacBook-Pro            │
│  │ M  │ 192.168.1.17:8888      │
│  └────┘                        │
│  ┌────┐ 🤖 LANClaw             │
│  │ 🤖 │ 192.168.1.5:8888  [AI] │
│  └────┘                        │
│                                │
│  离线 · 2                      │
│  ┌────┐ 书房台式机              │
│  │ 书 │ 最后在线 2 小时前       │
│  └────┘                        │
└────────────────────────────────┘
```

按**在线状态分组**（不是按拼音——设备数量不足以需要字母索引）。分组标题 11px，`--text-dim`，带数量。

设备项行高 56px（比会话项略矮，因为没有消息预览）。副行显示 `IP:端口`，离线设备显示「最后在线 x 前」。

手动添加的自定义设备加一个小标签（如 `手动`），和自动发现的区分开——因为它们的删除逻辑不同。

**关键决策：这里必须显示在线状态**

微信刻意不显示好友在线状态。**XChat 必须显示**，因为给离线设备发消息会进入 `pending`（待上线）状态，用户需要能预判这件事。不要照搬微信在这一点上的克制。

**右上角 ＋ 按钮**

打开「手动添加设备」面板（见 6.3），用于跨 VLAN / WireGuard 场景。

**右键菜单**

发消息、复制 IP、删除（仅离线设备可删）。

**空状态**

没发现任何设备时：插画 + 「局域网里还没有发现其他设备」+ 副文案提示检查防火墙是否放行了 TCP/UDP 端口 + 「手动添加设备」按钮。这个空状态很重要，因为防火墙是最常见的首次使用障碍。

### 5.3 聊天详情（内容区）

```
┌──────────────────────────────────────────────┐
│  张三                                    ⋯   │
│  192.168.1.42:8888 · 在线                    │
├──────────────────────────────────────────────┤
│                                              │
│   ┌──────────────┐                           │
│   │ 你好         │                           │
│   └──────────────┘                           │
│     14:30                                    │
│                                              │
│                          ┌──────────────┐    │
│                          │ 收到         │    │
│                          └──────────────┘    │
│                                  14:32       │
│                                              │
│                                        ⌄     │
├──────────────────────────────────────────────┤
│  📎  ┌────────────────────────┐              │
│      │ 输入消息...             │      发送     │
│      └────────────────────────┘              │
└──────────────────────────────────────────────┘
```

**顶栏（56px）**

左：对方名称（14px/600）+ 副行 `IP:端口 · 在线状态`（11px，`--text-dim`）。
右：`⋯` 更多菜单，收纳「多选消息」「清空聊天记录」「设备信息」。

桌面端多栏布局下**不需要返回按钮**（当前实现有，那是为移动端准备的）。

`⋯` 左侧再放一个信息面板开关图标，控制第四栏的展开 / 折叠。

**消息区**

- 上下内边距 16px，左右 24px
- 消息之间垂直间距 12px
- 气泡最大宽度 = 内容区宽度的 65%
- 向上滚动触发历史消息懒加载（保留现有行为），加载时顶部显示细条 loading
- 右下角「回到底部」悬浮圆按钮，仅在向上滚动超过一屏时出现；有新消息时按钮上叠加未读数

**日期分隔（新增）**

跨天的消息之间插入居中的日期分隔线（`—— 昨天 ——`）。当前实现是每条消息都带完整时间戳，跨天场景下很啰嗦。

**输入区（结构需重构）**

当前实现是把附件按钮和发送按钮**绝对定位盖在 textarea 内部**，靠 padding 让位。这套方案脆弱且难维护，改成**flex 行布局**，三个元素平级：

```
[📎 附件]  [输入框 flex:1]  [发送]
```

- 输入框 textarea，自动增高，上限 200px（保留现有逻辑）
- 回车发送，Shift+Enter 换行（保留）
- 发送按钮在输入为空时禁用（视觉上降低不透明度）
- 多选模式下发送按钮变为「删除 (n)」，用危险色

**拖拽上传**

整个内容区作为拖放目标。拖入时显示覆盖层：半透明遮罩 + 虚线边框 + 居中「释放以发送文件」。保留现有的呼吸动画。

**空状态**

未选中任何会话时，消息区显示居中的品牌占位 + 「选择一个会话开始聊天」。

### 5.4 设备信息面板（第四栏，240px，默认折叠）

```
┌──────────────────────┐
│      ┌──────┐        │
│      │  张  │        │
│      └──────┘        │
│       张三           │
│      ● 在线          │
├──────────────────────┤
│  地址                │
│  192.168.1.42:8888   │
│  发现方式            │
│  UDP 自动发现         │
│  最后在线            │
│  刚刚                │
├──────────────────────┤
│  文件 · 3            │
│  📄 季度报告.pdf      │
│  🖼 截图.png          │
│  📦 日志.zip          │
├──────────────────────┤
│  清空聊天记录         │
│  删除设备             │
└──────────────────────┘
```

三段结构：

1. **身份区** — 居中大头像（64×64，圆角 12px）+ 名称 + 在线状态
2. **元数据区** — 键值对，键 11px `--text-tertiary`，值 13px `--text-secondary`。「发现方式」区分 `UDP 自动发现` / `手动添加`
3. **文件清单** — 本会话内传输过的文件，点击行为与消息流里的文件卡片一致（打开所在目录）。这一段解决一个真实痛点：文件混在聊天记录里，往回翻很费劲
4. **管理操作** — 「清空聊天记录」用普通文字按钮，「删除设备」用危险色，仅离线设备可用

面板内容与顶栏 `⋯` 菜单有重叠（清空记录、设备信息）。这是有意的：菜单是快捷方式，面板是常驻视图。但**不要在面板里重复放「多选消息」**，那是消息区的操作。

### 5.5 消息气泡的六种形态

这是渲染逻辑最复杂的部分（现有 `createMessageElement`），需要为每一种给出视觉规格。

**形态 1：纯文本**

标准气泡。发出（`.sent`）靠右、强调色底；收到（`.received`）靠左、面板色底。圆角 12px，但靠近头像那一侧的角改为 4px（气泡"尖角"指向发送者）。

**形态 2：图片**

内联缩略图，最大 240×240，保持比例，圆角 8px。不套气泡背景（图片自己就是内容）。点击放大查看。加载失败降级为文件卡片。

传输中：缩略图上覆盖半透明遮罩 + 居中环形进度。

**形态 3：文件卡片**

```
┌─────────────────────────────────┐
│  📄   季度报告.pdf               │
│       2.4 MB · 待接收            │
└─────────────────────────────────┘
```

宽度固定 280px。左侧文件类型图标 40×40（按扩展名区分：文档 / 表格 / 压缩包 / 代码 / 音视频 / 未知）。右侧两行：文件名（单行省略，中间截断保留扩展名）+ 状态行。

传输中形态（**新增进度条**）：

```
┌─────────────────────────────────┐
│  📄   季度报告.pdf               │
│       ████████░░░░  1.2/2.4 MB  │
│       3.2 MB/s                  │
└─────────────────────────────────┘
```

后端已经在推送实时速度，进度百分比是现成数据。当前只显示 `xx MB/s` 而没有进度条，是明显的信息缺失。

**形态 4：AI 思考块**

LANClaw 机器人的 reasoning 内容。默认折叠成一行「💭 思考中…」/「💭 思考过程」，点击展开。展开后用等宽字体、更低的文字对比度、左侧一条竖线标识。

**形态 5：AI 工具调用 / 结果**

可折叠卡片，与思考块同一套折叠交互。工具调用显示工具名 + 参数摘要；结果显示输出，`is_error` 时用危险色边框。

**形态 6：模型选择器**

`[MODEL_LIST]` 前缀触发。当前渲染成一列裸按钮，视觉上和消息流割裂。改为**卡片内嵌选项列表**：

```
┌─────────────────────────────────┐
│  当前模型：claude-opus-4         │
│  ─────────────────────────────  │
│  ○ Claude Opus 4    anthropic   │
│  ○ GPT-4o           openai      │
│  ● Gemini 2.0       google      │
└─────────────────────────────────┘
```

**统一要求：形态 4/5/6 用同一套"卡片"视觉语言**（同样的边框、圆角、内边距、折叠箭头）。当前三者各写各的样式，是视觉割裂的主要来源。

## 6. 文件传输状态机（8 态，完整规格）

这是本产品的核心状态语言，必须每个状态都有明确视觉。

| 角色 | 状态值 | 显示文案 | 视觉 | 可交互 |
|---|---|---|---|---|
| 发送端 | `pending` | 待上线 | 中性灰 + 呼吸动画 | 否 |
| 发送端 | `offering` | 待接收 | 中性灰 + 呼吸动画 | 否 |
| 发送端 | `uploading` | `x/y MB` + `n MB/s` | 进度条 + 强调色 | 取消 |
| 发送端 | `sent` | 文件大小 | 无状态装饰 | 打开所在目录 |
| 接收端 | `offered` | 未下载 | 强调色文字 + 下载图标 | **点击下载** |
| 接收端 | `downloading` | `x/y MB` + `n MB/s` | 进度条 + 强调色 | 取消 |
| 接收端 | `accepted` | 文件大小 | 无状态装饰 | 打开所在目录 |
| 接收端 | `invalid` | 已失效 | 危险色 + 警告图标 | **重新请求** |

两处新增交互：

1. **`uploading` / `downloading` 可取消。** 当前无法中断一个正在传输的大文件。
2. **`invalid` 可重新请求。** 当前是死状态，用户只能干瞪眼。

关于「自动下载」开关：关闭时收到的文件停在 `offered`，需要手动点击。这个设置项要在设置面板里说清楚它的后果。

## 8. 设计语言

**现有配色全部作废。** 原实现是 Dracula 系暗紫（`--primary: #bd93f9`），与参照图无关，不要沿用。

### 8.1 主色（橙）

参照图深浅双版共用同一个橙色主色，这是产品唯一的品牌记忆点。请以参照图取色为准，并围绕它定义完整色阶：

```css
--primary          /* 主色本体：选中会话整行实底、发出气泡、主按钮、聚焦边框 */
--primary-hover    /* 悬停，比主色深一档 */
--primary-active    /* 按下，再深一档 */
--primary-subtle   /* 主色 8~12% 透明底：悬停高亮、次级标签底 */
--primary-on       /* 主色之上的文字色（白），需自行验证对比度 ≥ 4.5:1 */
```

**主色是稀缺资源。** 参照图里选中会话是整行橙色实底，视觉权重极高——正因如此，橙色不能同时用在别处（不要橙色的分组标题、橙色的图标栏、橙色的次要按钮）。一屏之内大面积橙色只应出现一次：当前选中的那一行。发出的消息气泡是第二处，但它在另一个视觉区域，不冲突。

### 8.2 双主题令牌

两套主题各自定义下列语义令牌，**类名与变量名完全相同**，只切换 `:root` 下的取值（或用 `[data-theme="dark"]` 覆盖）。设计稿需两版都出。

```css
--bg-base        /* 窗口最底层 */
--bg-surface     /* 列表栏、信息面板背景 */
--bg-raised      /* 卡片、收到的消息气泡、输入框 */
--bg-hover       /* 列表项悬停 */
--border-subtle  /* 栏间分隔线 */
--border-default /* 输入框、卡片描边 */
--text-primary   /* 会话名、消息正文 */
--text-secondary /* 消息预览、副行信息 */
--text-tertiary  /* 时间戳、分组标题 */
--text-on-primary/* 橙色实底之上的文字 */
```

浅色版注意：参照图的浅色不是纯白，列表栏与消息区之间有细微的层次差。不要把所有背景都做成 `#fff` 再靠边框分隔。

深色版注意：不要用纯黑。深色版的橙色在暗底上会显得更亮更跳，必要时允许**只降饱和度不改色相**。

### 8.3 语义色

现有 CSS 里 `--success` 被使用但**从未定义**（`style.css:47` 等处），是个实际存在的 bug。新设计需补全：

```css
--success   /* 在线状态点、传输完成 */
--warning   /* 待上线 / 待接收 */
--danger    /* 已失效、删除操作、未读气泡 */
--info      /* 传输中进度条 */
```

**`--info` 不要用主色。** 传输中的进度条如果也是橙色，会和"选中会话"抢视觉焦点——而文件传输往往正发生在非当前会话里。用一个区分度明确的中性偏冷色。

**`--danger` 与主色需要拉开距离。** 橙色和常规的红色在小尺寸元素（6px 状态点、18px 未读气泡）上很容易混淆。未读气泡建议偏正红、高饱和，与橙色主色形成明确差异；请在实际尺寸下验证可辨识度，而非只看色板。

### 8.4 头像调色板

8 色，按 `hash(device_id) % 8` 取色。要求：

- 与橙色主色**都能共存**——列表选中态是橙色实底，头像叠在其上仍需可辨
- 8 色之间两两可区分（这是头像方案的全部意义）
- 深浅两版各出一套（浅色版用中饱和度深色块配白字，深色版用低饱和度色块配亮字）
- LANClaw 机器人不参与哈希，固定专属色 + 🤖

### 8.5 圆角

参照图头像是**圆角方形**，不是圆形——保持这一点，它比圆形更贴近桌面 IM 的观感。

收敛为三档：`4px`（小元素、标签）/ `8px`（头像、卡片、输入框）/ `12px`（气泡、对话框）。胶囊单独用 `9999px`（未读气泡）。

现有四个圆角变量（16/10/50/12px）用得比较随意，一并作废。

### 8.6 字号阶梯

| 用途 | 字号 / 字重 |
|---|---|
| 会话名、顶栏标题 | 14 / 600 |
| 正文、消息文本 | 14 / 400 |
| 消息预览、副信息 | 13 / 400 |
| 时间戳、分组标题、标签 | 11 / 400 |

字体沿用系统字体栈（`-apple-system, Segoe UI, Roboto`）。**不要引入需要下载的 Web Font**——离线局域网工具不能依赖网络加载字体。现有 CSS 里声明了 `'Inter'` 但没有内嵌字体文件，实际总是回退到系统字体，可以直接去掉。

### 8.7 动效

克制。列表和消息不做入场动画（会拖慢高频操作的感知速度）。只保留：

- 对话框弹出 160ms
- 悬停态过渡 120ms
- 传输中状态的呼吸动画（现有 `status-breath`，保留）
- 拖拽覆盖层的脉冲动画（保留）
- 信息面板展开 / 折叠 200ms，宽度过渡

**主题切换不做过渡动画。** 全局颜色渐变会产生大面积重绘拖影，直接瞬切。

## 10. 技术约束（不可协商）

设计方案必须在这些约束下可实现：

1. **零依赖原生 HTML/CSS/JS。** 无构建步骤、无框架、无包管理器、无图标库。图标必须是内联 SVG，图表必须手写。项目规范（`AGENTS.md`）明确要求保持这一点。
2. **不下载外部资源。** 无 CDN、无 Web Font、无远程图片。局域网工具必须完全离线可用。
3. **CSP 限制。** 现有策略只允许 `'self'`、`asset:`、`data:` 和 `http://127.0.0.1:*` 的图片源，样式允许 `unsafe-inline`。
4. **i18n 机制。** 所有静态文本通过 `data-i18n` 属性驱动，中英双语。设计稿里的每一处文案都需要同时给出中英两版，且要考虑英文通常更长（按 1.4 倍预留宽度）。
5. **主题机制。** 用户可以把自定义 CSS 放到 `~/.config/lanchat/`（Windows 为 `%APPDATA%\.config\lanchat`）来覆盖样式。新设计需要提供清晰稳定的类名体系和 CSS 变量，让主题作者有明确的覆盖点。

**现有代码体量参考**：`ui.js` 3607 行，`style.css` 2433 行。这次是大改，不是微调。

## 13. 需要产品方拍板的问题

**Q1：是否接受破坏现有用户主题？**

新设计会大面积更换 CSS 类名和全部颜色变量，配置目录下所有用户自定义主题会失效，内置的 `vscode.css`（1015 行）需要重写或废弃。

- 方案 B：保留旧类名做别名层。但这等于背着旧结构做新设计，长期是负债。

**Q2：配置目录是否跟随更名？**

产品从 LANChat 改名 XChat，但配置和数据目录仍是 `~/.config/lanchat/`、`com.lanchat.app`、`lanchat.db`。改目录需要迁移逻辑，不改则界面与磁盘路径不一致（设置面板里会显示 `lanchat.db`）。这是工程决策，不阻塞设计——设计稿里的路径按占位处理即可。
